@@Q 1 | Introduction, REPL and process model

@@S A

@@I The [[console]] global object is used in a Node.js file to print output to the terminal.
For example `console.log('Hello')`. It is available everywhere without `require()`.

@@I Node.js uses a single-threaded, event-driven, and [[non-blocking]] I/O model to handle concurrency efficiently.
Also called **asynchronous** I/O.

@@I [[AJAX]] is a browser-side technique for making asynchronous requests, whereas Node.js is a server-side runtime.
AJAX stands for Asynchronous JavaScript and XML.

@@I Node.js uses a blocking I/O model, meaning it must wait for a file operation or database query to finish before moving to the next task. True or False?
@@TF False
Node.js uses **non-blocking** I/O. It starts the file or database work, moves on to the next task, and handles the result later in a callback.

@@S B

@@I What is the purpose of the Node.js REPL environment?
**REPL (Read–Eval–Print–Loop)** is Node's interactive shell. Its purpose is to **quickly try and test JavaScript code without creating a file**: we type a line, Node runs it and prints the result at once. It is used to test small expressions, explore modules and objects, and debug or learn.

```console
$ node
> const os = require('os')
> os.platform()
'win32'
> [1, 2, 3].map(n => n * 2)
[ 2, 4, 6 ]
> .exit
```

@@I What is the core distinction between Node.js and JavaScript?
**JavaScript is a programming language. Node.js is a runtime environment** that runs JavaScript **outside the browser** (on servers and computers) using Google's V8 engine.

| JavaScript in the browser | JavaScript in Node.js |
|---|---|
| Can use the page: `document`, `window` | No page, so no `document` or `window` |
| Cannot read or write files on the computer | Can use files, network and OS through `fs`, `http`, `os` |
| Used for the front end | Used mainly for the back end (servers, APIs, tools) |

@@S C

@@I List three advantages or features of Node.js.
1. **Asynchronous and non-blocking (event-driven).** Node does not wait for slow work such as reading a file or a database query. It moves to the next request and handles the result through a callback, so many users are served at the same time.
2. **Very fast.** Node runs on Google's **V8 engine**, which compiles JavaScript directly into machine code.
3. **Single-threaded but highly scalable.** One event loop can handle thousands of connections using little memory, which suits chat apps, APIs and live updates.

Other features: one language (JavaScript) for both front end and back end, a **huge NPM library** of free packages, and it is **open source and cross-platform** (Windows, Linux, macOS).

@@I Differentiate between Node.js, JQuery, and Angular JS.
All three use JavaScript, but they do very different jobs: **Node.js** runs on the **server**, while **jQuery** and **AngularJS** run in the **browser**.

| Point | Node.js | jQuery | AngularJS |
|---|---|---|---|
| Type | Runtime environment | JavaScript **library** | JavaScript **framework** |
| Runs on | Server | Browser | Browser |
| Main purpose | Servers, APIs, real-time apps | Easy DOM changes, events, animations, AJAX | Single-page applications (SPA) |
| Structure | Event-driven, non-blocking I/O | No fixed structure | MVC |
| Data binding | Not applicable | None (we update the page by hand) | Two-way, with `ng-model` |
| Made by | Ryan Dahl, 2009 | John Resig, 2006 | Google, 2010 |
| Use it when | You need a back end | You want small effects on a page | You build a full front-end app |

#### Small example of each

```js
// Node.js: a tiny web server (runs on the server)
require('http').createServer((req, res) => res.end('Hi from server')).listen(3000);
```

```html
<!-- jQuery: hide a paragraph when the button is clicked -->
<button id="btn">Hide</button>
<p id="msg">Hello</p>
<script>
  $('#btn').click(function () { $('#msg').hide(); });
</script>
```

```html
<!-- AngularJS: text updates as you type (two-way binding) -->
<div ng-app="">
  <input ng-model="name">
  <p>Hello {{ name }}</p>
</div>
```

#### Key differences in short

- **Node.js** works with files, databases and the network; it never touches a web page directly.
- **jQuery** makes writing browser code shorter, but we still change the page step by step ourselves.
- **AngularJS** gives a full structure (modules, controllers, services) and updates the page automatically when the data changes.

They are often used **together**: AngularJS or jQuery for the front end, and Node.js for the server that supplies the data.
