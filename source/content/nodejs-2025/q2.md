@@S B

@@I What is the use of the Buffer class in Node.js?
The **Buffer** class is used to **handle raw binary data (bytes)**, such as data from files, network streams, images or encryption, which may not be plain text. A Buffer is a fixed-size block of memory, and the class is available globally without `require()`.

```js
const buf = Buffer.from('Hello');   // text to bytes
console.log(buf);                   // <Buffer 48 65 6c 6c 6f>
console.log(buf.toString());        // Hello
console.log(buf.length);            // 5
const blank = Buffer.alloc(10);     // 10 bytes filled with zeros
```

@@I How to access the global scope in a Node.js file?
Node has a special object called **`global`** (also available as **`globalThis`**). Anything we attach to it can be used in **every file** of the app without `require()`.

```js
// app.js
global.appName = 'Student Portal';   // put a value in the global scope
require('./other');

// other.js
console.log(appName);                // Student Portal
console.log(globalThis === global);  // true
```

Note: a variable made with `var`, `let` or `const` at the top of a file stays **local to that file** (module scope); it does not become global as it would in a browser. Built-in globals include `console`, `process`, `setTimeout` and `Buffer`.

@@I What is the purpose of the package.json file?
`package.json` is the **main information file (manifest) of a Node.js project**. It sits in the project's root folder and is created with `npm init` (or `npm init -y`).

- Stores **project details**: name, version, description, author, licence.
- Lists **dependencies** (packages needed to run the app) and **devDependencies** (needed only while developing).
- Defines **scripts**, shortcuts such as `npm start` and `npm run dev`.
- Sets the **entry file** (`main`).
- Lets anyone reinstall every package with one command, `npm install`, so `node_modules` never has to be shared.

```json
{
  "name": "student-portal",
  "version": "1.0.0",
  "main": "app.js",
  "scripts": {
    "start": "node app.js",
    "dev": "nodemon app.js"
  },
  "dependencies": {
    "express": "^4.21.0"
  },
  "devDependencies": {
    "nodemon": "^3.1.0"
  }
}
```

`^4.21.0` means version 4.21.0 or any newer 4.x version.

@@I List and explain types of modules with example.
A **module** is a separate file (or block) of JavaScript code with its own scope, which can be **reused** in other files. Node.js has **three types of modules**.

#### 1. Core (built-in) modules

They come **with Node.js**, so nothing needs to be installed. We load them by name with `require()`. Examples: `http`, `fs`, `path`, `os`, `url`, `events`, `querystring`, `util`, `crypto`.

```js
const os = require('os');
const path = require('path');

console.log('Platform:', os.platform());       // win32 (on Windows)
console.log(path.extname('notes.pdf'));        // .pdf
```

#### 2. Local (user-defined) modules

Files **we write ourselves** in our project. We share code with `module.exports` and load it with a relative path.

```js
// greet.js
module.exports.sayHello = (name) => `Hello, ${name}!`;
```

```js
// app.js
const greet = require('./greet');
console.log(greet.sayHello('Riya'));           // Hello, Riya!
```

#### 3. Third-party modules

Modules **made by other developers** and shared on the npm registry. We install them first, then load them by name. Examples: `express`, `mysql`, `lodash`, `multer`.

```bash
npm install lodash
```

```js
const _ = require('lodash');
console.log(_.capitalize('node js'));          // Node js
console.log(_.max([4, 9, 2]));                 // 9
```

#### Points to remember

- Each module has its **own scope**: its variables do not clash with other files.
- A module is **loaded once and cached**, so requiring it again is fast.
- Node also supports **ES modules** (`import` / `export`) in `.mjs` files or when `package.json` has `"type": "module"`.

@@I Describe the steps to create a custom module and use it in another file.
A **custom module** is our own reusable file of code. We **export** what other files may use, and **import** it where we need it.

#### Steps

1. **Create a file** for the module, for example `mathUtils.js`.
2. **Write the functions** and values in it.
3. **Export** what others should use with `module.exports` (anything not exported stays private).
4. In another file such as `app.js`, **import** it with `require('./mathUtils')`. The `./` means "this folder", and `.js` can be left out.
5. **Use** the imported functions.
6. **Run** the program with `node app.js`.

```tree
project/
├── mathUtils.js
└── app.js
```

```js
// mathUtils.js  (custom module)
const PI = 3.14159;

function add(a, b) { return a + b; }
function multiply(a, b) { return a * b; }
function circleArea(r) { return round(PI * r * r); }
function round(n) { return Math.round(n * 100) / 100; }   // private helper

module.exports = { PI, add, multiply, circleArea };
```

```js
// app.js
const { add, multiply, circleArea } = require('./mathUtils');

console.log('Sum:', add(10, 5));
console.log('Product:', multiply(4, 6));
console.log('Area:', circleArea(3));
```

```output
Sum: 15
Product: 24
Area: 28.27
```

#### Same module with ES module syntax

```js
// mathUtils.mjs
export function add(a, b) { return a + b; }

// app.mjs
import { add } from './mathUtils.mjs';
console.log(add(2, 3));   // 5
```

#### Points to remember

- `round()` was not exported, so `app.js` cannot use it; this keeps helper code private.
- Use either `module.exports = {...}` or `exports.name = ...`, but never write `exports = {...}`, because that breaks the link to `module.exports`.
- Custom modules keep the code organised, reusable and easier to test.
