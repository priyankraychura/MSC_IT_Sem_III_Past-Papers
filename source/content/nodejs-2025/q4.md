@@S B

@@I What is the purpose of the emit() method in EventEmitter?
`emit(eventName, ...args)` **fires (triggers) an event**. It calls every listener registered for that event, **one by one in the order they were added**, and passes the extra arguments to them. It returns `true` if the event had listeners, otherwise `false`.

```js
const EventEmitter = require('events');
const shop = new EventEmitter();

shop.on('sale', (item, price) => console.log(`Sold ${item} for Rs. ${price}`));
shop.emit('sale', 'Pen', 20);        // Sold Pen for Rs. 20
console.log(shop.emit('closed'));    // false, because no listener
```

@@I How is the once() method different from on()?
- **`on()`** adds a listener that runs **every time** the event is emitted.
- **`once()`** adds a listener that runs **only the first time**; after that it is **removed automatically**.

```js
emitter.on('login', () => console.log('on: user logged in'));
emitter.once('login', () => console.log('once: welcome message'));

emitter.emit('login');
emitter.emit('login');
```

```output
on: user logged in
once: welcome message
on: user logged in
```

@@I Write a basic Node.js statement to connect to a MySQL database.
First install the driver with `npm install mysql`. Then create a connection with the server details and call `connect()`.

```js
const mysql = require('mysql');

const con = mysql.createConnection({
  host: 'localhost',     // where MySQL is running
  user: 'root',          // MySQL user name
  password: '',          // MySQL password
  database: 'college'    // database to use
});

con.connect((err) => {
  if (err) {
    console.log('Connection failed:', err.message);
    return;
  }
  console.log('Connected to MySQL!');
});
```

```output
Connected to MySQL!
```

After connecting, SQL commands are run with `con.query(sql, callback)`, and `con.end()` closes the connection. (With MySQL 8, if you see an authentication error, use the `mysql2` package; the code stays the same.)

@@I Compare synchronous and asynchronous function calls in Node.js.
| Point | Synchronous call | Asynchronous call |
|---|---|---|
| Waiting | Waits for the task to finish before the next line (**blocking**) | Starts the task and moves on at once (**non-blocking**) |
| Result | Returned directly | Given later through a callback, Promise or `await` |
| In a server | One slow task makes every user wait | Many tasks are handled at the same time |
| Errors | Caught with `try...catch` | `err` in the callback, `.catch()`, or `try...catch` with `await` |
| Example | `fs.readFileSync()` | `fs.readFile()` |

```js
// Synchronous
console.log('1');
const text = fs.readFileSync('a.txt', 'utf8');
console.log('2: file read');
console.log('3');
// Output: 1, 2: file read, 3
```

```js
// Asynchronous
console.log('A');
fs.readFile('a.txt', 'utf8', () => console.log('C: file read'));
console.log('B');
// Output: A, B, C: file read
```

Node.js prefers asynchronous calls, because they keep the single main thread free for other work.

@@I Explain the EventEmitter class with example.
Node.js is **event-driven**: things happen in response to events, such as a request arriving or a file finishing loading. The **`EventEmitter`** class from the built-in **`events`** module lets us **create our own events** and respond to them.

#### How to use it

1. Load the class: `const EventEmitter = require('events');`
2. Create an object: `const emitter = new EventEmitter();` (or make a class that `extends EventEmitter`).
3. **Register** a listener with `on(eventName, function)`.
4. **Fire** the event with `emit(eventName, ...args)`; every listener of that event runs.

| Method | Use |
|---|---|
| `on()` / `addListener()` | Add a listener that runs every time |
| `once()` | Add a listener that runs only the first time |
| `emit()` | Fire an event and pass values |
| `off()` / `removeListener()` | Remove one listener |
| `removeAllListeners()` | Remove all listeners of an event |
| `listenerCount()` | Number of listeners for an event |

#### Example: a shop

```js
const EventEmitter = require('events');
const shop = new EventEmitter();

function sendBill(item, price) {
  console.log(`Bill: ${item} - Rs. ${price}`);
}

shop.on('order', sendBill);                                   // 1. listeners
shop.on('order', (item) => console.log(`Packing ${item}...`));
shop.once('order', () => console.log('First order of the day!'));
shop.on('error', (err) => console.log('Problem:', err.message));   // always handle errors

shop.emit('order', 'Notebook', 60);                           // 2. fire events
shop.emit('order', 'Pen', 20);
shop.emit('error', new Error('Out of stock'));

console.log('Listeners:', shop.listenerCount('order'));       // 3. inspect and remove
shop.off('order', sendBill);
console.log('After removing:', shop.listenerCount('order'));
```

```output
Bill: Notebook - Rs. 60
Packing Notebook...
First order of the day!
Bill: Pen - Rs. 20
Packing Pen...
Problem: Out of stock
Listeners: 2
After removing: 1
```

#### Explanation

- Listeners run **in the order they were added**, and they get the values passed to `emit()`.
- The `once()` listener ran only for the first order, then removed itself, so the count is 2.
- `off()` removed `sendBill`, leaving 1 listener.
- Always add an `'error'` listener; without it, emitting `'error'` would crash the program.

Many Node objects, such as the HTTP server (`'request'` event) and streams (`'data'`, `'end'`), are built on EventEmitter.

@@I Describe how to connect Node.js to a relational database, and perform INSERT and SELECT operations.
A **relational database** (such as MySQL) stores data in **tables of rows and columns** and is used through **SQL**. Node.js talks to it through a **driver package**; for MySQL we use `mysql` or `mysql2`.

#### Step 1: Prepare the database (in MySQL)

```sql
CREATE DATABASE college;
USE college;
CREATE TABLE students (
  id INT AUTO_INCREMENT PRIMARY KEY,
  name VARCHAR(50),
  course VARCHAR(20)
);
```

#### Step 2: Install the driver

```bash
npm install mysql2
```

#### Step 3: Connect, INSERT and SELECT

```js
const mysql = require('mysql2');

const con = mysql.createConnection({
  host: 'localhost', user: 'root', password: '', database: 'college'
});

con.connect((err) => {
  if (err) throw err;
  console.log('Connected');

  // INSERT a row; ? placeholders are filled from the array
  const sql = 'INSERT INTO students (name, course) VALUES (?, ?)';
  con.query(sql, ['Riya', 'MSc IT'], (err, result) => {
    if (err) throw err;
    console.log('Inserted, new id:', result.insertId);

    // SELECT all rows
    con.query('SELECT * FROM students', (err, rows) => {
      if (err) throw err;
      rows.forEach((r) => console.log(r.id, r.name, r.course));
      con.end();                                   // close the connection
    });
  });
});
```

```output
Connected
Inserted, new id: 1
1 Riya MSc IT
```

#### Same work with async / await

```js
const mysql = require('mysql2/promise');

async function main() {
  const db = await mysql.createConnection({
    host: 'localhost', user: 'root', password: '', database: 'college'
  });
  await db.execute('INSERT INTO students (name, course) VALUES (?, ?)', ['Aman', 'MCA']);
  const [rows] = await db.execute('SELECT * FROM students');
  console.log(rows);
  await db.end();
}
main();
```

#### Points to remember

- Always use **`?` placeholders** for values; they protect against **SQL injection**.
- `result.insertId` gives the new row's id and `result.affectedRows` gives how many rows changed.
- Several rows can be inserted together with `VALUES ?` and a nested array.
- Close the connection with `end()` when the work is finished.
