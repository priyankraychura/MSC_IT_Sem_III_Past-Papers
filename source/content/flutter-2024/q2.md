@@I What is MediaQuery?
`MediaQuery` gives **information about the device screen and settings**: screen width and height, orientation, pixel ratio, text scale and safe-area padding (notch, status bar). We use it to build **responsive** layouts.

```dart
final size = MediaQuery.of(context).size;
bool isPortrait = MediaQuery.of(context).orientation == Orientation.portrait;

Container(width: size.width * 0.8);   // 80% of the screen width
```

@@I How to debug UI issues in Flutter?
- **Widget Inspector (DevTools):** tap any widget on screen to see its place in the widget tree, its size, padding and constraints.
- **Layout Explorer:** shows how a `Row` or `Column` divides space and helps fix overflow.
- **Debug paint:** set `debugPaintSizeEnabled = true;` to draw borders and padding lines on every widget.
- **Read the overflow error:** the yellow-and-black striped bar means a widget is too big. The console tells by how many pixels. Fix it with `Expanded`, `Flexible` or `SingleChildScrollView`.
- Use **hot reload** to try fixes quickly and `debugPrint()` to print values.

@@I Give difference between Stateless and Stateful widgets.
| Point | StatelessWidget | StatefulWidget |
|---|---|---|
| Data | Cannot change after it is built | Has **state** that can change |
| Rebuild | Only when its parent sends new data | Calls **`setState()`** to rebuild itself |
| Classes | One class | Two classes: the widget and its `State` class |
| Main methods | `build()` | `createState()`, `initState()`, `build()`, `dispose()` |
| Examples | `Text`, `Icon`, a fixed About screen | `Checkbox`, `TextField`, counter, forms |

```dart
class Greeting extends StatelessWidget {          // stateless
  final String name;
  const Greeting({super.key, required this.name});

  @override
  Widget build(BuildContext context) => Text('Hello $name');
}

class Counter extends StatefulWidget {            // stateful
  const Counter({super.key});
  @override
  State<Counter> createState() => _CounterState();
}

class _CounterState extends State<Counter> {
  int count = 0;

  @override
  Widget build(BuildContext context) {
    return ElevatedButton(
      onPressed: () => setState(() => count++),   // changes state, rebuilds
      child: Text('Clicked $count times'),
    );
  }
}
```

@@I Explain SliverAppBar widget.
`SliverAppBar` is an **app bar that changes while the user scrolls**. It can start large (for example with a cover photo), shrink as the list scrolls up, stay pinned at the top, or float back into view. It must be used inside a **`CustomScrollView`** together with other slivers such as `SliverList`.

| Property | Meaning |
|---|---|
| `expandedHeight` | Height when fully open |
| `flexibleSpace` | Content that shrinks, usually a `FlexibleSpaceBar` with title and background |
| `pinned` | Keeps a small bar visible at the top after collapsing |
| `floating` | Bar comes back as soon as the user scrolls up a little |
| `snap` | With `floating`, the bar opens or closes fully in one go |

```dart
CustomScrollView(
  slivers: [
    SliverAppBar(
      expandedHeight: 200,
      pinned: true,
      flexibleSpace: FlexibleSpaceBar(
        title: Text('My Profile'),
        background: Image.asset('assets/cover.jpg', fit: BoxFit.cover),
      ),
    ),
    SliverList(
      delegate: SliverChildBuilderDelegate(
        (context, i) => ListTile(title: Text('Item $i')),
        childCount: 30,
      ),
    ),
  ],
)
```

@@I Explain the layout and widgets hierarchy with example.
In Flutter, the whole screen is a **tree of widgets**, called the **widget hierarchy** or widget tree. A parent widget holds child widgets, and those children can hold their own children. **Layout widgets** decide where and how big their children are.

#### Types of layout widgets

- **Single-child layout widgets** – hold one child: `Container`, `Center`, `Padding`, `Align`, `SizedBox`, `Expanded`.
- **Multi-child layout widgets** – hold a list of children: `Row`, `Column`, `Stack`, `ListView`, `GridView`, `Wrap`.

#### How layout works (the main rule)

**Constraints go down, sizes go up, and the parent sets the position.** A parent tells each child the minimum and maximum size it may take. The child picks its size within those limits and reports it back. Then the parent places the child.

#### Example: a profile screen

```dart
MaterialApp(
  home: Scaffold(
    appBar: AppBar(title: Text('Profile')),
    body: Center(
      child: Column(
        mainAxisAlignment: MainAxisAlignment.center,
        children: [
          Icon(Icons.person, size: 80),
          Text('Ravi Patel', style: TextStyle(fontSize: 24)),
          Row(
            mainAxisAlignment: MainAxisAlignment.center,
            children: [Icon(Icons.email), Text(' ravi@mail.com')],
          ),
        ],
      ),
    ),
  ),
)
```

@@I Explain custom widget creation in Flutter.
A **custom widget** is our own widget, made by **combining existing widgets** into one reusable piece. If the same card or button appears many times, we create it once as a custom widget and reuse it.

#### Why create custom widgets?

- **Reuse** – write once, use on many screens.
- **Clean code** – the `build()` method of each screen stays short.
- **Consistent look** – all copies look the same, and one change updates them all.

#### Steps

1. Create a class that extends **`StatelessWidget`** (or **`StatefulWidget`** if it has changing data).
2. Add **`final` fields** for the values it needs, and a constructor with named parameters.
3. Override **`build()`** and return the UI made from other widgets.
4. Use it like any built-in widget and pass the values.

#### Example: a reusable info card

```dart
class InfoCard extends StatelessWidget {
  final IconData icon;
  final String title;
  final String subtitle;

  const InfoCard({super.key, required this.icon, required this.title, required this.subtitle});

  @override
  Widget build(BuildContext context) {
    return Card(
      margin: const EdgeInsets.all(8),
      child: ListTile(
        leading: Icon(icon, color: Colors.indigo),
        title: Text(title, style: const TextStyle(fontWeight: FontWeight.bold)),
        subtitle: Text(subtitle),
      ),
    );
  }
}
```

```dart
// Using it on a screen
Column(
  children: const [
    InfoCard(icon: Icons.phone, title: 'Phone', subtitle: '98765 43210'),
    InfoCard(icon: Icons.email, title: 'Email', subtitle: 'ravi@mail.com'),
    InfoCard(icon: Icons.home, title: 'City', subtitle: 'Rajkot'),
  ],
)
```

#### A stateful custom widget

```dart
class LikeButton extends StatefulWidget {
  const LikeButton({super.key});
  @override
  State<LikeButton> createState() => _LikeButtonState();
}

class _LikeButtonState extends State<LikeButton> {
  bool liked = false;

  @override
  Widget build(BuildContext context) {
    return IconButton(
      icon: Icon(liked ? Icons.favorite : Icons.favorite_border, color: Colors.red),
      onPressed: () => setState(() => liked = !liked),
    );
  }
}
```

**Tips:** keep each custom widget in its own file (for example `widgets/info_card.dart`) and use `const` constructors where possible, which helps performance.
