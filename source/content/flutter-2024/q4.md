@@I What is JSON serialization?
**Serialization** means turning a **Dart object into JSON text** (to send to a server or save it). **Deserialization** is the reverse: turning **JSON text back into a Dart object**. `dart:convert` gives `jsonEncode()` and `jsonDecode()`, and we add `toJson()` and `fromJson()` to the model class.

```dart
class Student {
  final String name;
  final int age;
  Student(this.name, this.age);

  factory Student.fromJson(Map<String, dynamic> j) => Student(j['name'], j['age']);
  Map<String, dynamic> toJson() => {'name': name, 'age': age};
}

String text = jsonEncode(Student('Riya', 21).toJson());   // {"name":"Riya","age":21}
Student s = Student.fromJson(jsonDecode(text));
```

For big apps, the `json_serializable` package can generate this code automatically.

@@I What is Hive in Flutter?
**Hive** is a **lightweight and very fast NoSQL database** written in pure Dart. It saves data as **key–value pairs inside boxes** (a box is like a table). It works offline on mobile, desktop and web and needs no native setup.

```dart
await Hive.initFlutter();
var box = await Hive.openBox('settings');
box.put('name', 'Ravi');
print(box.get('name'));   // Ravi
```

It is a good choice for app settings, cached data and offline data. Custom objects are stored with **TypeAdapters**.

@@I Explain caching data in Flutter.
**Caching** means **keeping a copy of data on the device**, so the app can show it **quickly**, work **offline**, and make fewer network calls.

**Ways to cache in Flutter:**

- **In-memory cache** – keep data in a variable or `Map`. Fastest, but lost when the app closes.
- **Disk cache** – `shared_preferences` for small values, **Hive** or **sqflite** for larger structured data, or files saved with `path_provider`.
- **Image cache** – the `cached_network_image` package saves downloaded pictures.
- **File cache** – `flutter_cache_manager` keeps downloaded files with an expiry time.

**Common strategy:** try the network; if it works, save a fresh copy; if it fails, show the saved copy.

```dart
Future<String> getQuote() async {
  final prefs = await SharedPreferences.getInstance();
  try {
    final res = await http.get(Uri.parse('https://api.example.com/quote'));
    await prefs.setString('quote', res.body);          // save a copy
    return res.body;
  } catch (e) {
    return prefs.getString('quote') ?? 'No data yet';  // offline: use the copy
  }
}
```

@@I Explain the use of WebSockets for real-time communication in Flutter.
A **WebSocket** is a **connection that stays open** between the app and the server. Both sides can send messages **at any time** (two-way, real time). With normal HTTP, the app must ask again and again for new data. Uses: **chat apps, live scores, stock prices, live location, multiplayer games**.

In Flutter we use the **`web_socket_channel`** package:

- **Connect:** `WebSocketChannel.connect(Uri.parse('wss://...'))`
- **Send:** `channel.sink.add('message')`
- **Receive:** listen to `channel.stream`, usually with a `StreamBuilder`
- **Close:** `channel.sink.close()` in `dispose()`

```dart
final channel = WebSocketChannel.connect(Uri.parse('wss://echo.websocket.events'));

StreamBuilder(
  stream: channel.stream,
  builder: (context, snapshot) =>
      Text(snapshot.hasData ? 'Server: ${snapshot.data}' : 'Waiting...'),
);

ElevatedButton(
  onPressed: () => channel.sink.add('Hello server'),
  child: const Text('Send'),
);

@override
void dispose() {
  channel.sink.close();
  super.dispose();
}
```

@@I Explain Shared preferences and secure storage in Flutter.
Both are used to **save data permanently on the device**, so it is still there after the app is closed. The difference is **security**.

#### 1. SharedPreferences

The `shared_preferences` package stores **small, simple data as key–value pairs**. It uses SharedPreferences on Android and NSUserDefaults on iOS.

- Supports `int`, `double`, `bool`, `String` and `List<String>`.
- Used for settings such as dark mode, language, "first launch" flag, or a username.
- Data is **not encrypted**, so never store passwords or tokens here.

```dart
final prefs = await SharedPreferences.getInstance();

await prefs.setBool('darkMode', true);          // save
await prefs.setString('username', 'ravi');

bool dark = prefs.getBool('darkMode') ?? false; // read (with default)
await prefs.remove('username');                 // delete one key
```

#### 2. Secure storage

The `flutter_secure_storage` package stores **sensitive data in encrypted form**. It uses the **Keychain** on iOS and **Keystore-based encryption** on Android.

- Used for login tokens, passwords, API keys and PINs.
- Main methods: `write()`, `read()`, `delete()`, `deleteAll()`.

```dart
const storage = FlutterSecureStorage();

await storage.write(key: 'token', value: 'eyJhbGciOi...');   // save
String? token = await storage.read(key: 'token');            // read
await storage.delete(key: 'token');                          // delete (logout)
```

#### Comparison

| Point | SharedPreferences | Secure storage |
|---|---|---|
| Package | `shared_preferences` | `flutter_secure_storage` |
| Encrypted? | No | Yes |
| Best for | Settings and flags | Tokens, passwords, keys |
| Speed | Very fast | A little slower (encryption) |

So, use **SharedPreferences for normal settings** and **secure storage for anything secret**.

@@I How to perform CRUD operations on a SQLite database in Flutter? Explain with example.
**SQLite** is a small database stored as a file on the device. Flutter uses it through the **`sqflite`** plugin. **CRUD** means **Create, Read, Update, Delete**.

#### Step 1: Add packages

```yaml
dependencies:
  sqflite: ^2.3.0
  path: ^1.9.0
```

#### Step 2: Model class

```dart
class Student {
  final int? id;
  final String name;
  final int age;
  Student({this.id, required this.name, required this.age});

  Map<String, dynamic> toMap() => {'id': id, 'name': name, 'age': age};
  factory Student.fromMap(Map<String, dynamic> m) =>
      Student(id: m['id'], name: m['name'], age: m['age']);
}
```

#### Step 3: Open the database and write CRUD methods

```dart
import 'package:sqflite/sqflite.dart';
import 'package:path/path.dart';

class DBHelper {
  static Database? _db;

  static Future<Database> get db async {
    _db ??= await openDatabase(
      join(await getDatabasesPath(), 'school.db'),
      version: 1,
      onCreate: (db, version) => db.execute(
        'CREATE TABLE students(id INTEGER PRIMARY KEY AUTOINCREMENT, name TEXT, age INTEGER)',
      ),
    );
    return _db!;
  }

  static Future<int> insert(Student s) async =>                       // Create
      (await db).insert('students', s.toMap());

  static Future<List<Student>> getAll() async {                       // Read
    final rows = await (await db).query('students');
    return rows.map((r) => Student.fromMap(r)).toList();
  }

  static Future<int> update(Student s) async =>                       // Update
      (await db).update('students', s.toMap(), where: 'id = ?', whereArgs: [s.id]);

  static Future<int> delete(int id) async =>                          // Delete
      (await db).delete('students', where: 'id = ?', whereArgs: [id]);
}
```

#### Step 4: Use it

```dart
await DBHelper.insert(Student(name: 'Riya', age: 21));
List<Student> all = await DBHelper.getAll();
await DBHelper.update(Student(id: 1, name: 'Riya Shah', age: 22));
await DBHelper.delete(1);
```

| Operation | sqflite method | SQL behind it |
|---|---|---|
| Create | `insert()` | `INSERT INTO students ...` |
| Read | `query()` | `SELECT * FROM students` |
| Update | `update()` | `UPDATE students SET ... WHERE id = ?` |
| Delete | `delete()` | `DELETE FROM students WHERE id = ?` |

#### Points to remember

- All methods are **asynchronous** (they return a `Future`), so we use `await`.
- `where: 'id = ?'` with `whereArgs` keeps the query safe from SQL injection.
- Show the records on screen with a `FutureBuilder` or by calling `setState()` after loading.
