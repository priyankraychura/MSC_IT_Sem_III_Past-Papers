@@Q 4 | Routing

@@S A

@@I What is routing in angularJS?
Routing lets a single-page app **show different views for different URLs without reloading the page**. In AngularJS it is done with the `ngRoute` module (`$routeProvider` and `ng-view`).

@@I The router is a part of @angular/core model. True/false?
@@TF False
The router is in its own package, **`@angular/router`**, not in `@angular/core`.

@@I Define routerOutlet.
`<router-outlet>` is a directive that acts as a **placeholder** in the template. Angular shows the component of the current route at that place.

@@I Which function is used to import RouterModule in a feature module?
**`RouterModule.forChild(routes)`**. (`forRoot()` is used only once, in the root module.)

@@S B

@@I What is ngRoute module?
`ngRoute` is an **AngularJS module that adds routing** to an app, so we can move between views without a page reload. It comes in a separate file, `angular-route.js`, and gives us:

- `$routeProvider` – to define the routes
- `$routeParams` – to read values from the URL
- `ng-view` – the place where the matched view is shown

```html
<script src="angular-route.js"></script>
<script>
  var app = angular.module('myApp', ['ngRoute']);   // add ngRoute as a dependency
</script>
```

@@I Differentiate RouterModule.forRoot() v/s RouterModule.forChild().
| Point | `forRoot()` | `forChild()` |
|---|---|---|
| Used in | Root module (`AppModule` / `AppRoutingModule`) | Feature modules, including lazy-loaded ones |
| How many times | **Only once** in the whole app | In every feature module that has routes |
| Router service | Creates the Router service and adds main routes | Only adds extra routes; uses the same Router |
| Example | `RouterModule.forRoot(appRoutes)` | `RouterModule.forChild(adminRoutes)` |

@@S C

@@I Explain $routeProvider and $routeParams.
**`$routeProvider`** is used inside `app.config()` to **define routes**. Each `.when(path, {...})` says which template and controller to show for a URL, and `.otherwise()` sets the default route.

**`$routeParams`** is a service that **gives the values from the URL**. If the route is `/student/:id` and the URL is `#!/student/7`, then `$routeParams.id` is `"7"`.

```js
var app = angular.module('myApp', ['ngRoute']);

app.config(function ($routeProvider) {
  $routeProvider
    .when('/', { template: '<h2>Home page</h2>' })
    .when('/student/:id', { templateUrl: 'student.html', controller: 'StudentCtrl' })
    .otherwise({ redirectTo: '/' });
});

app.controller('StudentCtrl', function ($scope, $routeParams) {
  $scope.id = $routeParams.id;          // "7" for #!/student/7
});
```

```html
<a href="#!/">Home</a> | <a href="#!/student/7">Student 7</a>
<div ng-view></div>      <!-- the chosen view appears here -->
```

@@I What are the main components of Angular routing? Explain in brief.
- **Routes** – an array that maps a URL path to a component, like `{ path: 'about', component: AboutComponent }`.
- **RouterModule** – the module that brings routing; we register routes with `RouterModule.forRoot(routes)`.
- **`<router-outlet>`** – the placeholder where the matched component is displayed.
- **`routerLink`** – used on links instead of `href`, so the page does not reload: `<a routerLink="/about">About</a>`.
- **Router service** – to move to a page from code: `this.router.navigate(['/about'])`.
- **ActivatedRoute** – to read values of the current route, such as `id` in `/student/:id`.

```ts
const routes: Routes = [
  { path: '', component: HomeComponent },
  { path: 'about', component: AboutComponent },
  { path: 'student/:id', component: StudentComponent }
];

@NgModule({ imports: [RouterModule.forRoot(routes)], exports: [RouterModule] })
export class AppRoutingModule {}
```

@@I How would you handle wildcard routes in Angular Routing?
A **wildcard route** uses the path **`'**'`** (two stars). It **matches any URL** that did not match the other routes. We use it to show a **"404 – Page Not Found"** page or to send the user back to the home page.

#### Steps

1. Create a component for the error page: `ng generate component page-not-found`.
2. Add a route with `path: '**'` that loads this component.
3. Put the wildcard route **last** in the routes array.
4. (Optional) Add an empty-path route that redirects to home.

```ts
const routes: Routes = [
  { path: '', redirectTo: '/home', pathMatch: 'full' },   // default page
  { path: 'home', component: HomeComponent },
  { path: 'about', component: AboutComponent },
  { path: '**', component: PageNotFoundComponent }        // always last
];
```

```html
<!-- page-not-found.component.html -->
<h2>404 – Page not found</h2>
<a routerLink="/home">Go back home</a>
```

#### Why must it be the last route?

The router checks routes **from top to bottom** and uses the **first match**. Since `'**'` matches everything, any route written after it would never be reached.

#### Example

- `/home` shows `HomeComponent`.
- `/about` shows `AboutComponent`.
- `/xyz` matches no route, so `PageNotFoundComponent` is shown.

#### Other ways

- Redirect instead of showing a page: `{ path: '**', redirectTo: '/home' }`.
- In AngularJS the same job is done by `.otherwise({ redirectTo: '/' })` in `$routeProvider`.

Wildcard routes make the app user-friendly, because a wrong or old link shows a helpful page instead of a blank screen.

@@I Explain Router.navigate and Router.navigateByUrl methods.
Both methods are used to **change the page from TypeScript code**, for example after a login or a button click. First we inject the `Router` service in the constructor.

#### `navigate()`

- Takes an **array of path parts** (called commands), like `['/student', 7]`.
- The path can be **absolute** or **relative** to the current route (using `relativeTo`).
- Extra options such as `queryParams` and `fragment` can be added.

#### `navigateByUrl()`

- Takes a **complete URL string** (or a `UrlTree`), like `'/student/7'`.
- The URL is always treated as **absolute**, starting from the root.

```ts
import { Router, ActivatedRoute } from '@angular/router';

export class LoginComponent {
  constructor(private router: Router, private route: ActivatedRoute) {}

  goToStudent(id: number) {
    // goes to /student/7?tab=marks
    this.router.navigate(['/student', id], { queryParams: { tab: 'marks' } });
  }

  goToDashboard() {
    this.router.navigateByUrl('/dashboard');   // full path as a string
  }

  goToDetails() {
    this.router.navigate(['details'], { relativeTo: this.route });  // relative path
  }
}
```

| Point | `navigate()` | `navigateByUrl()` |
|---|---|---|
| Input | Array of path parts | Full URL string |
| Path type | Absolute or relative | Always absolute |
| Extra options | `queryParams`, `fragment`, `relativeTo` | Fewer options; URL is used as written |
| Example | `navigate(['/user', id])` | `navigateByUrl('/user/' + id)` |

Both methods return a **Promise** that becomes `true` when navigation succeeds. Use `navigate()` when building a path from values, and `navigateByUrl()` when you already have the full URL.
