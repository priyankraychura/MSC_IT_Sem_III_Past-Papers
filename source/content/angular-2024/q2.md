@@Q 2 | Data binding and directives

@@S A

@@I What is Data Binding in AngularJS?
Data binding is the **automatic syncing of data between the model (JavaScript data) and the view (HTML)**. When the data changes, the page updates by itself, and in two-way binding, user input updates the data too.

@@I Which Directive is used for Data Binding in AngularJS?
The **`ng-model`** directive is used for two-way data binding. (`ng-bind` and `{{ }}` give one-way binding.)

@@I ng-app Directive Defines and links AngularJS application to HTML. TRUE/FALSE?
@@TF True
`ng-app` marks the root element of the AngularJS application and starts (bootstraps) it automatically when the page loads.

@@I What is async in AngularJS?
`async` is a built-in **pipe** that waits for an Observable or Promise and shows its latest value in the template, for example `{{ students$ | async }}`. It also unsubscribes by itself when the component is removed.

@@S B

@@I Explain ng-init Directive.
`ng-init` is an AngularJS directive that **creates variables and gives them starting values** in the current scope, directly in the HTML.

```html
<div ng-app="" ng-init="name='Ravi'; marks=85">
  <p>{{ name }} scored {{ marks }} marks</p>
</div>
```

Output: **Ravi scored 85 marks**. In real apps, starting values are usually set in the controller; `ng-init` is handy for small demos.

@@I Explain ngif in angular.
`*ngIf` is a **structural directive**. It **adds** an element to the page when the condition is true and **removes** it from the DOM when the condition is false (it is not just hidden).

```html
<p *ngIf="isLoggedIn; else loginBox">Welcome back!</p>
<ng-template #loginBox>
  <button>Login</button>
</ng-template>
```

If `isLoggedIn` is true, "Welcome back!" is shown; otherwise the Login button is shown. (AngularJS uses `ng-if`; Angular 17+ also allows `@if (isLoggedIn) { ... }`.)

@@S C

@@I Differentiate Property Binding v/s String Interpolation.
Both send data **one way, from the component class to the view**. The difference is in how and where they are used.

| Point | String Interpolation | Property Binding |
|---|---|---|
| Syntax | `{{ value }}` | `[property]="value"` |
| Used for | Showing text on the page | Setting a property of an element, like `[src]`, `[disabled]` |
| Value type | Always turned into a **string** | Keeps the real type (true/false, number, object) |
| Example | `<h1>{{ title }}</h1>` | `<button [disabled]="isSaving">Save</button>` |

```ts
export class AppComponent {
  title = 'Student Portal';
  logoUrl = 'assets/logo.png';
  isSaving = true;
}
```

```html
<h1>{{ title }}</h1>                         <!-- interpolation -->
<img [src]="logoUrl">                        <!-- property binding -->
<button [disabled]="isSaving">Save</button>  <!-- needs a real boolean -->
```

Use interpolation for text and property binding for non-text values such as true/false.

@@I Give steps to create multiple module in Angular.
A big app is split into **feature modules** (for example Admin and Student) so each part is organised separately.

1. **Create the modules** with the CLI: `ng generate module admin` and `ng generate module student`.
2. **Create components inside each module:** `ng generate component admin/dashboard`. The CLI adds it to `AdminModule` automatically.
3. **Export** the component from its module so other modules can use it.
4. **Import** the feature modules into the root `AppModule`.
5. **Use** the component's selector, for example `<app-dashboard></app-dashboard>`, and run `ng serve`.

```ts
// admin/admin.module.ts
@NgModule({
  declarations: [DashboardComponent],
  imports: [CommonModule],
  exports: [DashboardComponent]          // step 3
})
export class AdminModule {}

// app.module.ts
@NgModule({
  declarations: [AppComponent],
  imports: [BrowserModule, AdminModule, StudentModule],   // step 4
  bootstrap: [AppComponent]
})
export class AppModule {}
```

Note: Angular 17+ creates standalone apps by default. To work with modules, create the project with `ng new my-app --no-standalone`.

@@I Describe ng-model for two way Data Binding process.
**Two-way data binding** means data flows **both ways**: from the model to the view, and from the view back to the model. In AngularJS this is done with the **`ng-model`** directive.

#### How the process works

1. `ng-model="name"` links the input box to `$scope.name` (it creates the variable if it does not exist).
2. **View to Model:** when the user types, AngularJS copies the new text into `$scope.name`.
3. **Model to View:** when code changes `$scope.name`, the input box and every `{{ name }}` on the page update.
4. AngularJS notices these changes through its **digest cycle**, which watches the scope for new values.

#### Example

```html
<div ng-app="myApp" ng-controller="FormCtrl">
  <input type="text" ng-model="name">
  <p>Hello, {{ name }}!</p>
  <button ng-click="reset()">Reset</button>
</div>

<script>
  angular.module('myApp', []).controller('FormCtrl', function ($scope) {
    $scope.name = 'Riya';                          // model to view
    $scope.reset = function () { $scope.name = ''; };
  });
</script>
```

As you type in the box, the "Hello" line changes at the same moment. Clicking **Reset** clears both.

#### Extra features of ng-model

- Adds CSS classes such as `ng-valid`, `ng-invalid`, `ng-dirty`, `ng-touched` for styling.
- Supports validation with `required`, `ng-minlength`, `type="email"`.
- In Angular (2+), the same idea is written as `[(ngModel)]="name"` (called "banana in a box") and needs `FormsModule`.

@@I Explain Form module and how you pass inputs and variables to components?
#### Part 1: Form modules

Angular gives two modules for building forms:

- **`FormsModule`** – for **template-driven forms**. The form is written mostly in HTML using `ngModel`, `ngForm` and `(ngSubmit)`. Good for simple forms.
- **`ReactiveFormsModule`** – for **reactive forms**. The form is built in TypeScript with `FormGroup` and `FormControl`. Good for large forms and complex validation.

We import the module before using form features:

```ts
import { FormsModule } from '@angular/forms';

@NgModule({
  imports: [BrowserModule, FormsModule],
  declarations: [AppComponent],
  bootstrap: [AppComponent]
})
export class AppModule {}
```

```html
<form #f="ngForm" (ngSubmit)="save(f.value)">
  <input name="city" [(ngModel)]="city" required>
  <button type="submit">Save</button>
</form>
```

#### Part 2: Passing inputs and variables to components

- **Parent to child – `@Input()`:** the child marks a property with `@Input()`, and the parent sends a value with property binding.
- **Child to parent – `@Output()`:** the child sends data back with an `EventEmitter`, and the parent listens with event binding.

```ts
// student.component.ts (child)
export class StudentComponent {
  @Input() studentName = '';                     // receives data
  @Output() selected = new EventEmitter<string>();

  pick() { this.selected.emit(this.studentName); }   // sends data back
}
```

```html
<!-- student.component.html -->
<p (click)="pick()">Student: {{ studentName }}</p>

<!-- app.component.html (parent) -->
<app-student [studentName]="name" (selected)="onSelect($event)"></app-student>
```

Here the parent's `name` variable goes into the child, and when the child is clicked, `onSelect()` in the parent receives the student name. So **FormsModule handles user input in forms**, and **`@Input` / `@Output` move data between components**.
