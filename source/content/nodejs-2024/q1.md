@@I What is REPL ?
**REPL** stands for **Read – Eval – Print – Loop**. It is Node's **interactive shell**, where we type JavaScript and see the result at once.

- **Read** – reads what we type
- **Eval** – runs (evaluates) it
- **Print** – shows the result
- **Loop** – waits for the next input

We start it by typing `node` in the terminal. Useful commands: `.help`, `.editor`, `.save`, `.load`, and `.exit` (or Ctrl+C twice).

```console
$ node
> 10 + 20
30
> _ * 2
60
> .exit
```

@@I List out NodeJS Console methods.
- `console.log()` – prints a normal message
- `console.info()` – prints an information message
- `console.warn()` – prints a warning
- `console.error()` – prints an error message
- `console.table()` – shows an array or object as a table
- `console.time()` / `console.timeEnd()` – measure how long code takes
- `console.count()` – counts how many times it was called
- `console.assert()` – prints an error only if a condition is false
- `console.dir()` – shows all properties of an object
- `console.clear()` – clears the console

@@I Differentiate : Node JS V/s. Angular JS
| Point | Node.js | AngularJS |
|---|---|---|
| What it is | A **runtime environment** that runs JavaScript outside the browser | A **front-end framework** for building web pages |
| Runs on | **Server** | **Browser** (client side) |
| Used for | Back-end work: servers, APIs, real-time apps | Front-end work: single-page applications |
| Written in | C, C++ and JavaScript | JavaScript |
| Design | Event-driven, non-blocking I/O | MVC (Model–View–Controller) |
| How we get it | Installed on the computer | Added to an HTML page with a `<script>` tag |

Both can work together: AngularJS shows the pages and Node.js serves the data (this is part of the MEAN stack).

@@I Differentiate : Node JS V/s. AJAX
| Point | Node.js | AJAX |
|---|---|---|
| What it is | A **server-side JavaScript runtime** | A **browser technique**: Asynchronous JavaScript and XML |
| Runs on | Server | Browser |
| Purpose | Build web servers, APIs and tools | Update part of a page **without reloading** it |
| Works with | V8 engine and modules like `http`, `fs` | `XMLHttpRequest` or `fetch()` |
| Can it create a server? | Yes | No, it only sends requests to a server |
| Example | A login API on the server | Live search suggestions while typing |

In real apps they work together: AJAX in the browser calls an API that is built with Node.js.

@@I How to create Node file with JavaScript ?
A Node file is a plain **JavaScript file with the `.js` extension** that we run with the `node` command instead of a browser.

#### Steps

1. **Install Node.js** from nodejs.org and check it with `node -v`.
2. **Make a project folder** and open it in the terminal.
3. (Optional) Create `package.json` with `npm init -y`.
4. **Create a file** such as `app.js` in VS Code or Notepad.
5. **Write JavaScript code** in it and save.
6. **Run it** with `node app.js` and see the output in the terminal.

```bash
mkdir myapp
cd myapp
npm init -y
node app.js
```

#### Example 1: a simple program

```js
// app.js
const name = 'Node.js';
const add = (a, b) => a + b;

console.log('Hello from ' + name);
console.log('Sum is', add(10, 20));
```

```output
Hello from Node.js
Sum is 30
```

#### Example 2: a web server file

```js
// server.js
const http = require('http');

const server = http.createServer((req, res) => {
  res.writeHead(200, { 'Content-Type': 'text/html' });
  res.end('<h1>My first Node server</h1>');
});

server.listen(3000, () => console.log('Server running at http://localhost:3000'));
```

Run `node server.js` and open `http://localhost:3000` in the browser. Press **Ctrl+C** to stop the server.

#### Points to remember

- Node has **no `window` or `document`**, because there is no web page; instead it has modules such as `fs` and `http`.
- Built-in modules are loaded with `require()`.
- The `nodemon` tool restarts the file automatically every time we save it.

@@I Explain Node JS process model.
The **process model** explains how Node.js handles many client requests at the same time. Node.js uses a **single-threaded, event-driven, non-blocking I/O** model.

#### Traditional web server model

Servers like Apache or IIS (classic setup) create **one thread for each request**. While a thread waits for a file or database, it sits idle (it is **blocked**). Thousands of users need thousands of threads, which uses a lot of memory.

1. Clients send requests, and Node places them in the **event queue**.
2. The **event loop**, running on **one main thread**, picks the requests one by one.
3. If a request is quick (no waiting), it is processed and the **response** is sent at once.
4. If a request needs slow I/O (reading a file, a database query, a network call), Node **hands it to the thread pool** (managed by the **libuv** library) and moves on to the next request **without waiting**.
5. When the slow work finishes, its **callback** goes back to the queue, and the event loop runs it and sends the response.

```js
const fs = require('fs');

console.log('1. Start');
fs.readFile('data.txt', 'utf8', (err, data) => {
  console.log('3. File reading finished');     // callback runs later
});
console.log('2. Next task runs without waiting');
```

```output
1. Start
2. Next task runs without waiting
3. File reading finished
```

#### Advantages

- One thread can serve **thousands of connections** using little memory.
- Very fast for I/O-heavy apps such as chat, APIs and streaming.

#### Limitation

**CPU-heavy work** (image processing, huge calculations) keeps the single thread busy and slows every user. For such work, Node offers worker threads or child processes.
