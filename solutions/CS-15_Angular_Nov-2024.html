What is Component? How many Components are there in angularJS?

A component is a reusable building block of the screen. A header, a menu or a student list can each be a component. Every component has three parts:

  • Template – the HTML that is shown
  • Class – the TypeScript code (data and functions)
  • Metadata – the @Component decorator that joins them (selector, template, styles)

How many? There is no fixed number. An app can have as many components as it needs. Every app starts with one root component (AppComponent), and all other components sit inside it like a tree. The command ng generate component hello creates 4 files for one component: .ts, .html, .css and .spec.ts (test).

TypeScript
import { Component } from '@angular/core';

@Component({
  selector: 'app-hello',                  // used in HTML as <app-hello>
  template: '<h2>Hello {{ name }}</h2>'
})
export class HelloComponent {
  name = 'Priya';
}

In AngularJS (version 1.5 and above), a component is made with app.component('hello', { template: '...', controller: function () {...} }).

Explain MVC Framework.

MVC stands for Model – View – Controller. It is a design pattern that divides an application into three parts, so that the data, the screen and the logic are kept separate. AngularJS follows this pattern.

  • Model – holds the data of the app. In AngularJS, data is stored on $scope.
  • View – what the user sees: the HTML page with expressions like {{ name }}.
  • Controller – the logic that connects Model and View. It reacts to user actions and updates the data. In AngularJS it is a JavaScript function attached with ng-controller.

Example in AngularJS

HTML
<div ng-app="myApp" ng-controller="StudentCtrl">
  <p>Name: {{ student.name }}</p>                <!-- View -->
  <button ng-click="changeName()">Change</button>
</div>

<script>
  var app = angular.module('myApp', []);
  app.controller('StudentCtrl', function ($scope) {   // Controller
    $scope.student = { name: 'Riya' };                 // Model
    $scope.changeName = function () {
      $scope.student.name = 'Aman';                    // View updates by itself
    };
  });
</script>

Advantages of MVC

  • Separation of work: design, data and logic stay in different places.
  • Easy to maintain: a change in the view does not break the logic.
  • Easy to test: controllers and models can be tested alone.
  • Teamwork: designers and developers can work at the same time.
  • Reusable code: one model can be shown in many views.

In short, MVC keeps an app organised, and AngularJS adds automatic data binding so the View and Model stay in sync.

Give steps to create multiple module in Angular.

  declarations: [AppComponent],
  imports: [BrowserModule, AdminModule, StudentModule],   // step 4

Describe ng-model for two way Data Binding process.

Two-way data binding means data flows both ways: from the model to the view, and from the view back to the model. In AngularJS this is done with the ng-model directive.

ng-model connects an input control (input, select, textarea) to a variable on $scope.

How the process works

  1. ng-model="name" links the input box to $scope.name (it creates the variable if it does not exist).
  2. View to Model: when the user types, AngularJS copies the new text into $scope.name.
  3. Model to View: when code changes $scope.name, the input box and every {{ name }} on the page update.
  4. AngularJS notices these changes through its digest cycle, which watches the scope for new values.

Example

HTML
<div ng-app="myApp" ng-controller="FormCtrl">
  <input type="text" ng-model="name">
  <p>Hello, {{ name }}!</p>
  <button ng-click="reset()">Reset</button>
</div>

<script>
  angular.module('myApp', []).controller('FormCtrl', function ($scope) {
    $scope.name = 'Riya';                          // model to view
    $scope.reset = function () { $scope.name = ''; };
  });
</script>

As you type in the box, the "Hello" line changes at the same moment. Clicking Reset clears both.

Extra features of ng-model

  • Adds CSS classes such as ng-valid, ng-invalid, ng-dirty, ng-touched for styling.
  • Supports validation with required, ng-minlength, type="email".
  • In Angular (2+), the same idea is written as [(ngModel)]="name" (called "banana in a box") and needs FormsModule.

Explain Form module and how you pass inputs and variables to components?

Part 1: Form modules

Angular gives two modules for building forms:

  • FormsModule – for template-driven forms. The form is written mostly in HTML using ngModel, ngForm and (ngSubmit). Good for simple forms.
  • ReactiveFormsModule – for reactive forms. The form is built in TypeScript with FormGroup and FormControl. Good for large forms and complex validation.

We import the module before using form features:

TypeScript
import { FormsModule } from '@angular/forms';

@NgModule({
  imports: [BrowserModule, FormsModule],
  declarations: [AppComponent],
  bootstrap: [AppComponent]
})
export class AppModule {}
HTML
<form #f="ngForm" (ngSubmit)="save(f.value)">
  <input name="city" [(ngModel)]="city" required>
  <button type="submit">Save</button>
</form>

Part 2: Passing inputs and variables to components

  • Parent to child – @Input(): the child marks a property with @Input(), and the parent sends a value with property binding.
  • Child to parent – @Output(): the child sends data back with an EventEmitter, and the parent listens with event binding.
TypeScript
// student.component.ts (child)
export class StudentComponent {
  @Input() studentName = '';                     // receives data
  @Output() selected = new EventEmitter<string>();

  pick() { this.selected.emit(this.studentName); }   // sends data back
}
HTML
<!-- student.component.html -->
<p (click)="pick()">Student: {{ studentName }}</p>

<!-- app.component.html (parent) -->
<app-student [studentName]="name" (selected)="onSelect($event)"></app-student>

Here the parent's name variable goes into the child, and when the child is clicked, onSelect() in the parent receives the student name. So FormsModule handles user input in forms, and @Input / @Output move data between components.

How to inject services in AngularJS? Explain with example.

To use a service, we write its name as a parameter of the controller (or another service). AngularJS's injector sees the name, creates the service once, and passes it in.

  1. Create the service with app.service() (or app.factory()).
  2. Inject it into a controller by name. The array form keeps it safe after minification.
  3. Call its methods inside the controller.

  function ($scope, MathService) {
    $scope.num = 4;
    $scope.result = MathService.square($scope.num);   // 3. use
  }]);

Explain Dependency Hierarchical Injector.

Angular does not have just one injector. It has a tree of injectors that follows the tree of components. This is called the hierarchical injector.

  • Root injector – services with providedIn: 'root' live here. One copy is shared by the whole app.
  • Module injector – providers listed in a module (lazy-loaded modules get their own child injector).
  • Component (element) injector – providers listed in @Component({ providers: [...] }). That component and its children get their own new copy.

When a component asks for a service, Angular checks the component's own injector first, then its parent, and keeps going up the tree to the root. The first match is used. If nothing is found, Angular throws NullInjectorError: No provider for ....

How to inject services into another services in angular?

A service can use another service, just like a component can. We inject it through the constructor of the service. The service that receives the other service must have the @Injectable() decorator, because that tells Angular it has dependencies to fill.

Steps

  1. Create the first service: ng generate service logger.
  2. Create the second service: ng generate service student.
  3. In StudentService, add LoggerService as a constructor parameter.
  4. Inject StudentService into a component and call its method.
TypeScript
// logger.service.ts
@Injectable({ providedIn: 'root' })
export class LoggerService {
  log(msg: string) { console.log('[LOG] ' + msg); }
}
TypeScript
// student.service.ts
@Injectable({ providedIn: 'root' })
export class StudentService {
  private students = ['Riya', 'Aman', 'Neha'];

  constructor(private logger: LoggerService) {}    // service inside a service

  getStudents() {
    this.logger.log('Student list fetched');
    return this.students;
  }
}
TypeScript
// student-list.component.ts
export class StudentListComponent implements OnInit {
  students: string[] = [];
  constructor(private studentService: StudentService) {}

  ngOnInit() { this.students = this.studentService.getStudents(); }
}
Output
[LOG] Student list fetched

Points to remember

  • Angular builds the chain by itself: it creates LoggerService first, then gives it to StudentService.
  • providedIn: 'root' makes one shared copy of each service.
  • Avoid circular dependency (A needs B and B needs A); Angular shows an error for it.
  • Newer code can also write private logger = inject(LoggerService); instead of a constructor parameter.
  • In AngularJS the idea is the same: app.service('StudentService', function (LoggerService) { ... }).

How to call REST API using HttpClient?

A REST API is a server URL that sends and receives data, usually as JSON. Angular calls it with the HttpClient service.

Step 1: Make HttpClient available

TypeScript
// app.module.ts
import { HttpClientModule } from '@angular/common/http';

@NgModule({
  imports: [BrowserModule, HttpClientModule],
  declarations: [AppComponent],
  bootstrap: [AppComponent]
})
export class AppModule {}

(In standalone apps, add provideHttpClient() to the providers in app.config.ts.)

Step 2: Create a service that calls the API

TypeScript
// user.service.ts
export interface User { id: number; name: string; }

@Injectable({ providedIn: 'root' })
export class UserService {
  private url = 'https://jsonplaceholder.typicode.com/users';
  constructor(private http: HttpClient) {}

  getUsers(): Observable<User[]> { return this.http.get<User[]>(this.url); }
  addUser(u: User)    { return this.http.post<User>(this.url, u); }
  updateUser(u: User) { return this.http.put<User>(`${this.url}/${u.id}`, u); }
  deleteUser(id: number) { return this.http.delete(`${this.url}/${id}`); }
}

Step 3: Subscribe in a component and show the data

TypeScript
export class UserListComponent implements OnInit {
  users: User[] = [];
  error = '';
  constructor(private userService: UserService) {}

  ngOnInit() {
    this.userService.getUsers().subscribe({
      next: data => this.users = data,
      error: () => this.error = 'Could not load users'
    });
  }
}
HTML
<ul>
  <li *ngFor="let u of users">{{ u.name }}</li>
</ul>
<p *ngIf="error">{{ error }}</p>
Method Use
get() Read data
post() Add new data
put() Update data
delete() Remove data

Points to remember

  • Every method returns an Observable. The request is sent only when we call subscribe().
  • The JSON response is turned into a JavaScript object automatically.
  • Handle failures in the error part (or with the catchError operator).

Explain $routeProvider and $routeParams.

$routeProvider is used inside app.config() to define routes. Each .when(path, {...}) says which template and controller to show for a URL, and .otherwise() sets the default route.

$routeParams is a service that gives the values from the URL. If the route is /student/:id and the URL is #!/student/7, then $routeParams.id is "7".

JavaScript
var app = angular.module('myApp', ['ngRoute']);

app.config(function ($routeProvider) {
  $routeProvider
    .when('/', { template: '<h2>Home page</h2>' })
    .when('/student/:id', { templateUrl: 'student.html', controller: 'StudentCtrl' })
    .otherwise({ redirectTo: '/' });
});

app.controller('StudentCtrl', function ($scope, $routeParams) {
  $scope.id = $routeParams.id;          // "7" for #!/student/7
});
HTML
<a href="#!/">Home</a> | <a href="#!/student/7">Student 7</a>
<div ng-view></div>      <!-- the chosen view appears here -->

How would you handle wildcard routes in Angular Routing?

A wildcard route uses the path '**' (two stars). It matches any URL that did not match the other routes. We use it to show a "404 – Page Not Found" page or to send the user back to the home page.

Steps

  1. Create a component for the error page: ng generate component page-not-found.
  2. Add a route with path: '**' that loads this component.
  3. Put the wildcard route last in the routes array.
  4. (Optional) Add an empty-path route that redirects to home.
TypeScript
const routes: Routes = [
  { path: '', redirectTo: '/home', pathMatch: 'full' },   // default page
  { path: 'home', component: HomeComponent },
  { path: 'about', component: AboutComponent },
  { path: '**', component: PageNotFoundComponent }        // always last
];
HTML
<!-- page-not-found.component.html -->
<h2>404 – Page not found</h2>
<a routerLink="/home">Go back home</a>

Why must it be the last route?

The router checks routes from top to bottom and uses the first match. Since '**' matches everything, any route written after it would never be reached.

Example

  • /home shows HomeComponent.
  • /about shows AboutComponent.
  • /xyz matches no route, so PageNotFoundComponent is shown.

Other ways

  • Redirect instead of showing a page: { path: '**', redirectTo: '/home' }.
  • In AngularJS the same job is done by .otherwise({ redirectTo: '/' }) in $routeProvider.

Wildcard routes make the app user-friendly, because a wrong or old link shows a helpful page instead of a blank screen.

Explain Router.navigate and Router.navigateByUrl methods.

Both methods are used to change the page from TypeScript code, for example after a login or a button click. First we inject the Router service in the constructor.

navigate()

  • Takes an array of path parts (called commands), like ['/student', 7].
  • The path can be absolute or relative to the current route (using relativeTo).
  • Extra options such as queryParams and fragment can be added.

navigateByUrl()

  • Takes a complete URL string (or a UrlTree), like '/student/7'.
  • The URL is always treated as absolute, starting from the root.
TypeScript
import { Router, ActivatedRoute } from '@angular/router';

export class LoginComponent {
  constructor(private router: Router, private route: ActivatedRoute) {}

  goToStudent(id: number) {
    // goes to /student/7?tab=marks
    this.router.navigate(['/student', id], { queryParams: { tab: 'marks' } });
  }

  goToDashboard() {
    this.router.navigateByUrl('/dashboard');   // full path as a string
  }

  goToDetails() {
    this.router.navigate(['details'], { relativeTo: this.route });  // relative path
  }
}
Point navigate() navigateByUrl()
Input Array of path parts Full URL string
Path type Absolute or relative Always absolute
Extra options queryParams, fragment, relativeTo Fewer options; URL is used as written
Example navigate(['/user', id]) navigateByUrl('/user/' + id)

Both methods return a Promise that becomes true when navigation succeeds. Use navigate() when building a path from values, and navigateByUrl() when you already have the full URL.

Explain ng-submit in form submission.

ng-submit connects a function to the form's submit event. The function runs when the user clicks a submit button or presses Enter inside a field. When the form has no action attribute, it also stops the page from reloading.

HTML
<div ng-app="myApp" ng-controller="RegCtrl">
  <form name="regForm" ng-submit="register()" novalidate>
    <input name="uname" ng-model="user.name" placeholder="Your name" required>
    <button type="submit" ng-disabled="regForm.$invalid">Register</button>
  </form>
  <p>{{ message }}</p>
</div>

<script>
  angular.module('myApp', []).controller('RegCtrl', function ($scope) {
    $scope.user = {};
    $scope.register = function () {
      $scope.message = 'Welcome, ' + $scope.user.name + '!';
    };
  });
</script>
  • Put ng-submit on the <form> tag, not on the button.
  • Do not also add ng-click to the submit button, or the function runs twice.
  • In Angular 2+, the same thing is written as (ngSubmit)="register()".

What are the built-in validators in Angular forms, and how do you use them?

Validators check what the user typed and mark a field as valid or invalid. Angular gives ready-made validators in the Validators class of @angular/forms.

Validator What it checks Template-driven form Reactive form
required Field is not empty required Validators.required
minlength At least n characters minlength="3" Validators.minLength(3)
maxlength At most n characters maxlength="10" Validators.maxLength(10)
pattern Matches a pattern (regex) pattern="[0-9]{10}" Validators.pattern('[0-9]{10}')
email Proper email format email Validators.email
min / max Number is in a range min="18" max="60" Validators.min(18), Validators.max(60)
requiredTrue Checkbox must be ticked required on a checkbox Validators.requiredTrue

1. Using validators in a template-driven form

We write them as HTML attributes on the input:

HTML
<form #f="ngForm">
  <input name="username" ngModel required minlength="3" #u="ngModel">
  <small *ngIf="u.touched && u.errors?.['required']">Name is required</small>
  <small *ngIf="u.errors?.['minlength']">Use at least 3 letters</small>
  <button [disabled]="f.invalid">Save</button>
</form>

2. Using validators in a reactive form

We pass them in the TypeScript code when creating each FormControl:

TypeScript
this.form = new FormGroup({
  email: new FormControl('', [Validators.required, Validators.email]),
  age:   new FormControl('', [Validators.min(18), Validators.max(60)]),
  phone: new FormControl('', Validators.pattern('[0-9]{10}'))
});
HTML
<form [formGroup]="form" (ngSubmit)="save()">
  <input formControlName="email" placeholder="Email">
  <small *ngIf="form.get('email')?.hasError('email')">Invalid email</small>
  <button [disabled]="form.invalid">Save</button>
</form>

Points to remember

  • Each failed rule appears in the control's errors object, such as { required: true }.
  • A control has status flags valid, invalid, touched, dirty.
  • Angular adds CSS classes ng-valid and ng-invalid, so we can colour wrong fields.
  • If built-in validators are not enough, we can write a custom validator function.

Explain different Mouse events in angularJS.

AngularJS has a directive for each mouse event. We put the directive on an element, and AngularJS runs the given expression when that event happens.

Directive Runs when
ng-click The element is clicked
ng-dblclick The element is double-clicked
ng-mousedown A mouse button is pressed down on the element
ng-mouseup The mouse button is released
ng-mouseenter The pointer enters the element
ng-mouseleave The pointer leaves the element
ng-mousemove The pointer moves inside the element
ng-mouseover The pointer moves onto the element or one of its children

Example

HTML
<div ng-app="" ng-init="count = 0; msg = 'Move the mouse here'">
  <div style="padding: 30px; border: 1px solid #999"
       ng-mouseenter="msg = 'Mouse entered'"
       ng-mouseleave="msg = 'Mouse left'"
       ng-mousemove="x = $event.offsetX; y = $event.offsetY"
       ng-click="count = count + 1"
       ng-dblclick="count = 0">
    {{ msg }} (X: {{ x }}, Y: {{ y }})
  </div>
  <p>Clicks: {{ count }} (double-click the box to reset)</p>
</div>

Points to remember

  • One click fires events in this order: mousedown, mouseup, click.
  • ng-mouseenter fires once when entering the element; ng-mouseover fires again for every child element the pointer moves over.
  • The special $event object gives details such as clientX, clientY and which button was pressed.

Mouse event directives let us make the page interactive (hover effects, counters, drawing) without writing DOM code by hand.
