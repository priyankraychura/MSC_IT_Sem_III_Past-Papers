Explain Hot Reload feature of flutter.

Hot reload puts our code changes into the running app in about one second, without restarting it and without losing its state (the current page, typed text, counter value stay as they are).

  • How: save the file in VS Code / Android Studio, or press r in the terminal running flutter run.
  • Flutter sends the changed code into the Dart VM and rebuilds the widgets.
  • Hot restart (R) restarts the app and clears the state. We need it after changing main(), initState() or global variables.

This makes designing screens and fixing bugs very fast.

Explain loops in Dart with example.

A loop repeats a block of code many times. Dart has these loops:

  • for – when we know how many times to repeat.
  • for-in – goes through each item of a list.
  • while – checks the condition first, then runs.
  • do-while – runs once first, then checks the condition, so it runs at least once.
  • forEach() – a method on lists that runs a function for every item.

break stops a loop, and continue skips to the next round.

Dart
void main() {
  for (int i = 1; i <= 3; i++) {          // for
    print('for: $i');
  }

  var fruits = ['Apple', 'Mango'];
  for (var f in fruits) {                 // for-in
    print('for-in: $f');
  }

  int n = 1;
  while (n <= 2) {                        // while
    print('while: $n');
    n++;
  }

  int m = 5;
  do {                                    // do-while runs once even though m < 5 is false
    print('do-while: $m');
    m++;
  } while (m < 5);

  fruits.forEach((f) => print('forEach: $f'));
}
Output
for: 1
for: 2
for: 3
for-in: Apple
for-in: Mango
while: 1
while: 2
do-while: 5
forEach: Apple
forEach: Mango

Explain Dart libraries.

A library is a collection of ready-made code (classes, functions, constants) that we import and use. Every Dart file is also a library.

1. Core libraries – come with the Dart SDK:

  • dart:core – basic types like int, String, List, and print(). It is imported automatically.
  • dart:math – sqrt(), max(), Random.
  • dart:async – Future and Stream for asynchronous code.
  • dart:convert – jsonEncode() and jsonDecode().
  • dart:io – files, sockets and HTTP (not on web).

2. Package libraries – downloaded from pub.dev, for example import 'package:http/http.dart' as http;

3. Custom libraries – our own files, for example import 'utils/helpers.dart';

Dart
import 'dart:math';
import 'dart:convert' show jsonEncode;   // import only jsonEncode

void main() {
  print(sqrt(25));                        // 5.0
  print(max(4, 9));                       // 9
  print(jsonEncode({'name': 'Ravi'}));    // {"name":"Ravi"}
}

Import options: as gives a prefix, show imports only some names, hide imports all except some. Names starting with _ are private to their library.

Explain Flutter Architecture with diagram.

Flutter has a layered architecture. Each layer is built on top of the layer below it, and the app we write sits at the very top. There are three main layers: Framework, Engine and Embedder.

1. Framework layer (Dart)

This is the part developers use every day. It has sub-layers:

  • Material and Cupertino – ready-made widgets in Android (Material) and iOS (Cupertino) style.
  • Widgets – the building blocks of the UI. We build screens by combining small widgets.
  • Rendering – works out the size and position (layout) of each widget and paints it.
  • Animation, Painting, Gestures – support for motion, drawing and touch input.
  • Foundation – basic classes and services used by all the layers above.

2. Engine layer (C/C++)

The engine is the core that makes Flutter run. It uses Skia / Impeller to draw graphics, does text layout, runs Dart code (the Dart runtime), and passes messages to native code through platform channels.

3. Embedder layer (platform-specific)

The embedder is written in the platform's own language (Kotlin/Java for Android, Swift/Objective-C for iOS, C++ for desktop). It gives the engine a surface to draw on, sends touch and keyboard input, and handles the app's life cycle.

Key points

  • Everything is a widget. The widget tree is turned into an element tree and then a render tree that is painted.
  • Flutter draws every pixel itself instead of using native controls, so the app looks the same on every device.
  • In release mode Dart is compiled ahead of time (AOT) to native code, which makes apps fast. In debug mode it uses JIT, which makes hot reload possible.

So, one Dart codebase runs on mobile, web and desktop because only the small embedder changes from platform to platform.

Explain the layout and widgets hierarchy with example.

In Flutter, the whole screen is a tree of widgets, called the widget hierarchy or widget tree. A parent widget holds child widgets, and those children can hold their own children. Layout widgets decide where and how big their children are.

Types of layout widgets

  • Single-child layout widgets – hold one child: Container, Center, Padding, Align, SizedBox, Expanded.
  • Multi-child layout widgets – hold a list of children: Row, Column, Stack, ListView, GridView, Wrap.

How layout works (the main rule)

Constraints go down, sizes go up, and the parent sets the position. A parent tells each child the minimum and maximum size it may take. The child picks its size within those limits and reports it back. Then the parent places the child.

Example: a profile screen

Dart
MaterialApp(
  home: Scaffold(
    appBar: AppBar(title: Text('Profile')),
    body: Center(
      child: Column(
        mainAxisAlignment: MainAxisAlignment.center,
        children: [
          Icon(Icons.person, size: 80),
          Text('Ravi Patel', style: TextStyle(fontSize: 24)),
          Row(
            mainAxisAlignment: MainAxisAlignment.center,
            children: [Icon(Icons.email), Text(' ravi@mail.com')],
          ),
        ],
      ),
    ),
  ),
)

Explanation

  • MaterialApp is the root and gives the app theme and navigation.
  • Scaffold gives the page structure with an appBar and a body.
  • Center places its child in the middle; Column stacks the icon, name and email row vertically.
  • The inner Row places the email icon and text horizontally.

Building screens by nesting small widgets like this keeps the code easy to read and lets us reuse parts.

Explain custom widget creation in Flutter.

A custom widget is our own widget, made by combining existing widgets into one reusable piece. If the same card or button appears many times, we create it once as a custom widget and reuse it.

Why create custom widgets?

  • Reuse – write once, use on many screens.
  • Clean code – the build() method of each screen stays short.
  • Consistent look – all copies look the same, and one change updates them all.

Steps

  1. Create a class that extends StatelessWidget (or StatefulWidget if it has changing data).
  2. Add final fields for the values it needs, and a constructor with named parameters.
  3. Override build() and return the UI made from other widgets.
  4. Use it like any built-in widget and pass the values.

Example: a reusable info card

Dart
class InfoCard extends StatelessWidget {
  final IconData icon;
  final String title;
  final String subtitle;

  const InfoCard({super.key, required this.icon, required this.title, required this.subtitle});

  @override
  Widget build(BuildContext context) {
    return Card(
      margin: const EdgeInsets.all(8),
      child: ListTile(
        leading: Icon(icon, color: Colors.indigo),
        title: Text(title, style: const TextStyle(fontWeight: FontWeight.bold)),
        subtitle: Text(subtitle),
      ),
    );
  }
}
Dart
// Using it on a screen
Column(
  children: const [
    InfoCard(icon: Icons.phone, title: 'Phone', subtitle: '98765 43210'),
    InfoCard(icon: Icons.email, title: 'Email', subtitle: 'ravi@mail.com'),
    InfoCard(icon: Icons.home, title: 'City', subtitle: 'Rajkot'),
  ],
)

A stateful custom widget

Dart
class LikeButton extends StatefulWidget {
  const LikeButton({super.key});
  @override
  State<LikeButton> createState() => _LikeButtonState();
}

class _LikeButtonState extends State<LikeButton> {
  bool liked = false;

  @override
  Widget build(BuildContext context) {
    return IconButton(
      icon: Icon(liked ? Icons.favorite : Icons.favorite_border, color: Colors.red),
      onPressed: () => setState(() => liked = !liked),
    );
  }
}

Tips: keep each custom widget in its own file (for example widgets/info_card.dart) and use const constructors where possible, which helps performance.

What is InheritedWidget?

InheritedWidget is a special widget that passes data down the widget tree. Any widget below it can read that data directly through context, without passing it through every constructor. When the data changes, only the widgets that use it are rebuilt.

Dart
class UserInfo extends InheritedWidget {
  final String name;
  const UserInfo({super.key, required this.name, required super.child});

  static UserInfo of(BuildContext context) =>
      context.dependOnInheritedWidgetOfExactType<UserInfo>()!;

  @override
  bool updateShouldNotify(UserInfo old) => name != old.name;
}
// Any child can now use: Text(UserInfo.of(context).name)

Theme.of(context) and MediaQuery.of(context) work this way, and the Provider package is built on it.

Explain Stream-based state management with RxDart.

A Stream is a flow of values over time, like water through a pipe. The UI listens to a stream with StreamBuilder and rebuilds whenever a new value arrives. RxDart is a package that adds extra power to Dart streams:

  • Subjects – a stream we can push values into. BehaviorSubject remembers the latest value and gives it to every new listener; PublishSubject sends only new values; ReplaySubject replays all old values.
  • Operators – tools such as map, where, distinct, debounceTime (wait until the user stops typing) and combineLatest.

Flow: the UI calls a method → the logic class adds a value to the subject → StreamBuilder receives it → the UI rebuilds.

Dart
import 'package:rxdart/rxdart.dart';

class CounterBloc {
  final _count = BehaviorSubject<int>.seeded(0);   // starts at 0
  Stream<int> get count => _count.stream;

  void increment() => _count.add(_count.value + 1);
  void dispose() => _count.close();
}
Dart
StreamBuilder<int>(
  stream: bloc.count,
  builder: (context, snapshot) => Text('Count: ${snapshot.data ?? 0}'),
)
// Button: ElevatedButton(onPressed: bloc.increment, child: Text('+'))

The logic stays outside the widgets, so it is easy to test and reuse.

Write a note on ScopedModel.

ScopedModel (scoped_model package) is a simple way to share data with many widgets and rebuild them when the data changes. It has three main parts:

  • Model – our data class extends Model and calls notifyListeners() whenever the data changes.
  • ScopedModel<T> – wraps a part of the widget tree and provides the model to it.
  • ScopedModelDescendant<T> – any widget below that uses the model. Its builder runs again when notifyListeners() is called.
Dart
class CounterModel extends Model {
  int count = 0;
  void increment() {
    count++;
    notifyListeners();            // tell listening widgets to rebuild
  }
}

ScopedModel<CounterModel>(
  model: CounterModel(),
  child: ScopedModelDescendant<CounterModel>(
    builder: (context, child, model) => TextButton(
      onPressed: model.increment,
      child: Text('Count: ${model.count}'),
    ),
  ),
)

ScopedModel is easy to learn, but it is an older package. Today Provider, which works in a very similar way, is the recommended choice.

Explain BLoC pattern for state management.

BLoC stands for Business Logic Component. It is a pattern that separates the business logic from the UI using streams. The UI only does two things: it sends events and it shows states.

How it works

  1. The user taps a button, so the UI adds an event (for example Increment) to the BLoC.
  2. The BLoC runs the logic (calculation, API call, database work).
  3. The BLoC emits a new state (for example count = 5).
  4. Widgets listening to the BLoC rebuild with the new state.

Main classes of the flutter_bloc package

  • Bloc / Cubit – hold the logic (Cubit is a simpler BLoC that uses methods instead of events).
  • BlocProvider – gives the BLoC to the widget tree.
  • BlocBuilder – rebuilds the UI when the state changes.
  • BlocListener – does one-time actions such as showing a SnackBar or navigating.

Example: counter

Dart
abstract class CounterEvent {}
class Increment extends CounterEvent {}
class Decrement extends CounterEvent {}

class CounterBloc extends Bloc<CounterEvent, int> {
  CounterBloc() : super(0) {                       // starting state = 0
    on<Increment>((event, emit) => emit(state + 1));
    on<Decrement>((event, emit) => emit(state - 1));
  }
}
Dart
BlocProvider(
  create: (_) => CounterBloc(),
  child: Builder(
    builder: (context) => Scaffold(
      body: Center(
        child: BlocBuilder<CounterBloc, int>(
          builder: (context, count) => Text('$count', style: const TextStyle(fontSize: 40)),
        ),
      ),
      floatingActionButton: FloatingActionButton(
        onPressed: () => context.read<CounterBloc>().add(Increment()),
        child: const Icon(Icons.add),
      ),
    ),
  ),
)

Advantages

  • UI and logic are separate, so the code is clean and easy to test.
  • State changes are predictable: one event in, one state out.
  • The same BLoC can be reused on different screens.

The only drawback is some extra code (events and states classes), which is worth it for medium and large apps.

Explain Redux architecture for Flutter.

Redux is a state management pattern (first made for JavaScript) that keeps the whole app state in one place, called the store, and allows data to flow in only one direction. In Flutter we use it with the redux and flutter_redux packages.

Main parts

  • Store – one object that holds the complete app state (single source of truth).
  • State – the data; it is never changed directly.
  • Action – a simple object that says what happened, like IncrementAction.
  • Reducer – a pure function (oldState, action) => newState that creates the new state.
  • Middleware (optional) – runs between the action and the reducer, for API calls or logging.

Example: counter with flutter_redux

Dart
enum CounterAction { increment }

int counterReducer(int state, dynamic action) {   // pure function
  if (action == CounterAction.increment) return state + 1;
  return state;
}

void main() {
  final store = Store<int>(counterReducer, initialState: 0);

  runApp(StoreProvider<int>(
    store: store,
    child: MaterialApp(
      home: Scaffold(
        body: Center(
          child: StoreConnector<int, String>(
            converter: (store) => store.state.toString(),
            builder: (context, count) => Text(count, style: const TextStyle(fontSize: 40)),
          ),
        ),
        floatingActionButton: FloatingActionButton(
          onPressed: () => store.dispatch(CounterAction.increment),
          child: const Icon(Icons.add),
        ),
      ),
    ),
  ));
}

Three principles of Redux

  1. Single source of truth – the whole state is in one store.
  2. State is read-only – the only way to change it is to dispatch an action.
  3. Changes are made by pure functions – reducers return a new state without side effects.

Advantages: predictable behaviour, easy debugging and testing. Drawback: a lot of extra code, so it suits large apps more than small ones.

What is JSON serialization?

Serialization means turning a Dart object into JSON text (to send to a server or save it). Deserialization is the reverse: turning JSON text back into a Dart object. dart:convert gives jsonEncode() and jsonDecode(), and we add toJson() and fromJson() to the model class.

Dart
class Student {
  final String name;
  final int age;
  Student(this.name, this.age);

  factory Student.fromJson(Map<String, dynamic> j) => Student(j['name'], j['age']);
  Map<String, dynamic> toJson() => {'name': name, 'age': age};
}

String text = jsonEncode(Student('Riya', 21).toJson());   // {"name":"Riya","age":21}
Student s = Student.fromJson(jsonDecode(text));

For big apps, the json_serializable package can generate this code automatically.

What is Hive in Flutter?

Hive is a lightweight and very fast NoSQL database written in pure Dart. It saves data as key–value pairs inside boxes (a box is like a table). It works offline on mobile, desktop and web and needs no native setup.

Explain caching data in Flutter.

Caching means keeping a copy of data on the device, so the app can show it quickly, work offline, and make fewer network calls.

Ways to cache in Flutter:

  • In-memory cache – keep data in a variable or Map. Fastest, but lost when the app closes.
  • Disk cache – shared_preferences for small values, Hive or sqflite for larger structured data, or files saved with path_provider.
  • Image cache – the cached_network_image package saves downloaded pictures.
  • File cache – flutter_cache_manager keeps downloaded files with an expiry time.

Common strategy: try the network; if it works, save a fresh copy; if it fails, show the saved copy.

Dart
Future<String> getQuote() async {
  final prefs = await SharedPreferences.getInstance();
  try {
    final res = await http.get(Uri.parse('https://api.example.com/quote'));
    await prefs.setString('quote', res.body);          // save a copy
    return res.body;
  } catch (e) {
    return prefs.getString('quote') ?? 'No data yet';  // offline: use the copy
  }
}

Explain the use of WebSockets for real-time communication in Flutter.

A WebSocket is a connection that stays open between the app and the server. Both sides can send messages at any time (two-way, real time). With normal HTTP, the app must ask again and again for new data. Uses: chat apps, live scores, stock prices, live location, multiplayer games.

In Flutter we use the web_socket_channel package:

  • Connect: WebSocketChannel.connect(Uri.parse('wss://...'))
  • Send: channel.sink.add('message')
  • Receive: listen to channel.stream, usually with a StreamBuilder
  • Close: channel.sink.close() in dispose()
Dart
final channel = WebSocketChannel.connect(Uri.parse('wss://echo.websocket.events'));

  builder: (context, snapshot) =>
      Text(snapshot.hasData ? 'Server: ${snapshot.data}' : 'Waiting...'),
);

ElevatedButton(
  onPressed: () => channel.sink.add('Hello server'),
  child: const Text('Send'),
);

@override
void dispose() {
  channel.sink.close();
  super.dispose();
}

Explain Shared preferences and secure storage in Flutter.

Both are used to save data permanently on the device, so it is still there after the app is closed. The difference is security.

1. SharedPreferences

The shared_preferences package stores small, simple data as key–value pairs. It uses SharedPreferences on Android and NSUserDefaults on iOS.

  • Supports int, double, bool, String and List<String>.
  • Used for settings such as dark mode, language, "first launch" flag, or a username.
  • Data is not encrypted, so never store passwords or tokens here.
Dart
final prefs = await SharedPreferences.getInstance();

await prefs.setBool('darkMode', true);          // save
await prefs.setString('username', 'ravi');

bool dark = prefs.getBool('darkMode') ?? false; // read (with default)
await prefs.remove('username');                 // delete one key

2. Secure storage

The flutter_secure_storage package stores sensitive data in encrypted form. It uses the Keychain on iOS and Keystore-based encryption on Android.

  • Used for login tokens, passwords, API keys and PINs.
  • Main methods: write(), read(), delete(), deleteAll().
Dart
const storage = FlutterSecureStorage();

await storage.write(key: 'token', value: 'eyJhbGciOi...');   // save
String? token = await storage.read(key: 'token');            // read
await storage.delete(key: 'token');                          // delete (logout)

Comparison

Point SharedPreferences Secure storage
Package shared_preferences flutter_secure_storage
Encrypted? No Yes
Best for Settings and flags Tokens, passwords, keys
Speed Very fast A little slower (encryption)

So, use SharedPreferences for normal settings and secure storage for anything secret.

How to perform CRUD operations on a SQLite database in Flutter? Explain with example.

SQLite is a small database stored as a file on the device. Flutter uses it through the sqflite plugin. CRUD means Create, Read, Update, Delete.

Step 1: Add packages

YAML
dependencies:
  sqflite: ^2.3.0
  path: ^1.9.0

Step 2: Model class

Dart
class Student {
  final int? id;
  final String name;
  final int age;
  Student({this.id, required this.name, required this.age});

  Map<String, dynamic> toMap() => {'id': id, 'name': name, 'age': age};
  factory Student.fromMap(Map<String, dynamic> m) =>
      Student(id: m['id'], name: m['name'], age: m['age']);
}

Step 3: Open the database and write CRUD methods

Dart
import 'package:sqflite/sqflite.dart';
import 'package:path/path.dart';

class DBHelper {
  static Database? _db;

  static Future<Database> get db async {
    _db ??= await openDatabase(
      join(await getDatabasesPath(), 'school.db'),
      version: 1,
      onCreate: (db, version) => db.execute(
        'CREATE TABLE students(id INTEGER PRIMARY KEY AUTOINCREMENT, name TEXT, age INTEGER)',
      ),
    );
    return _db!;
  }

  static Future<int> insert(Student s) async =>                       // Create
      (await db).insert('students', s.toMap());

  static Future<List<Student>> getAll() async {                       // Read
    final rows = await (await db).query('students');
    return rows.map((r) => Student.fromMap(r)).toList();
  }

  static Future<int> update(Student s) async =>                       // Update
      (await db).update('students', s.toMap(), where: 'id = ?', whereArgs: [s.id]);

  static Future<int> delete(int id) async =>                          // Delete
      (await db).delete('students', where: 'id = ?', whereArgs: [id]);
}

Step 4: Use it

Dart
await DBHelper.insert(Student(name: 'Riya', age: 21));
List<Student> all = await DBHelper.getAll();
await DBHelper.update(Student(id: 1, name: 'Riya Shah', age: 22));
await DBHelper.delete(1);
Operation sqflite method SQL behind it
Create insert() INSERT INTO students ...
Read query() SELECT * FROM students
Update update() UPDATE students SET ... WHERE id = ?
Delete delete() DELETE FROM students WHERE id = ?

Points to remember

  • All methods are asynchronous (they return a Future), so we use await.
  • where: 'id = ?' with whereArgs keeps the query safe from SQL injection.
  • Show the records on screen with a FutureBuilder or by calling setState() after loading.

Explain Push notifications in Flutter using Firebase.

A push notification is a message sent from a server to the user's phone, which appears even when the app is closed. Flutter apps receive them with Firebase Cloud Messaging (FCM).

  1. Create a project in the Firebase console and connect the app with flutterfire configure.
  2. Add the packages firebase_core and firebase_messaging.
  3. Start Firebase in main() with Firebase.initializeApp().
  4. Ask permission to show notifications (needed on iOS and Android 13+).
  5. Get the device token with getToken(); the server uses it to send to this phone.
  6. Handle messages: onMessage (app open), onBackgroundMessage (app in background or closed), onMessageOpenedApp (user tapped the notification).
  7. Send a test message from Firebase console → Messaging.
Dart
void main() async {
  WidgetsFlutterBinding.ensureInitialized();
  await Firebase.initializeApp(options: DefaultFirebaseOptions.currentPlatform);

  final fcm = FirebaseMessaging.instance;
  await fcm.requestPermission();
  print('Token: ${await fcm.getToken()}');

  FirebaseMessaging.onMessage.listen((msg) {
    print('New message: ${msg.notification?.title}');
  });
  runApp(const MyApp());
}

Explain animation techniques – Flare and Lottie.

Flutter can animate widgets with code (AnimationController, Tween), but complex animations such as characters or illustrated loaders are easier to make in a design tool and then play inside the app. Flare (now Rive) and Lottie are the two popular ways.

1. Flare (now called Rive)

  • Flare was a 2D design and animation tool; it is now called Rive. Designers draw and animate in the Rive editor and export a file (.flr in old Flare, .riv in Rive).
  • Animations are vector based, so they stay sharp at any size and the files are small.
  • Rive state machines make animations interactive: they can react to taps, hover or values from the app (for example a login character that covers its eyes while you type a password).
  • Package: rive (the old package was flare_flutter).
Dart
// Rive
RiveAnimation.asset('assets/truck.riv');

// Old Flare package
FlareActor('assets/robot.flr', animation: 'idle', fit: BoxFit.contain);

2. Lottie

  • Lottie animations are made in Adobe After Effects and exported as a JSON file with the Bodymovin plugin. Thousands of free ones are on LottieFiles.
  • Used for loading spinners, success ticks, onboarding and empty-screen pictures.
  • Package: lottie.
Dart
Lottie.asset('assets/loading.json', width: 150, repeat: true);
Lottie.network('https://example.com/success.json');

Steps to use either one

  1. Add the package (rive or lottie) to pubspec.yaml.
  2. Put the animation file in assets/ and list it under flutter: assets:.
  3. Show it with the widget (RiveAnimation.asset or Lottie.asset).
  4. Control it if needed (play, pause, repeat) with a controller.

Comparison

Point Flare / Rive Lottie
Made in Rive (Flare) editor Adobe After Effects
File type .riv (.flr in old Flare) .json
Interactive Yes, with state machines Mostly plays as recorded
Package rive lottie

Both give rich, smooth animations with very little code, which makes apps feel more polished.

Explain Internationalisation and localization in Flutter.

  • Internationalization (i18n) means preparing the app to support many languages and regions: no hard-coded text, and dates, numbers and currency formatted by locale.
  • Localization (l10n) means adding the actual translations and formats for each language, for example English, Hindi and Gujarati.

Steps (official Flutter method)

1. Add packages in pubspec.yaml and turn on code generation:

YAML
dependencies:
  flutter:
    sdk: flutter
  flutter_localizations:
    sdk: flutter
  intl: any
flutter:
  generate: true

2. Create l10n.yaml in the project root:

YAML
arb-dir: lib/l10n
template-arb-file: app_en.arb
output-localization-file: app_localizations.dart

3. Add one ARB file per language in lib/l10n/:

JSON
// app_en.arb
{ "hello": "Hello", "welcome": "Welcome, {name}!" }

// app_hi.arb
{ "hello": "नमस्ते", "welcome": "स्वागत है, {name}!" }

4. Run flutter gen-l10n (it also runs on every build). Flutter creates the AppLocalizations class.

5. Connect it in MaterialApp and use the text:

Dart
import 'l10n/app_localizations.dart';   // older Flutter: package:flutter_gen/gen_l10n/app_localizations.dart

MaterialApp(
  localizationsDelegates: AppLocalizations.localizationsDelegates,
  supportedLocales: AppLocalizations.supportedLocales,
  home: Builder(
    builder: (context) => Text(AppLocalizations.of(context)!.hello),
  ),
);

Formatting dates and money with intl

Dart
DateFormat.yMMMd('hi').format(DateTime.now());                        // date in Hindi format
NumberFormat.currency(locale: 'en_IN', symbol: '₹').format(150000);   // ₹1,50,000.00

Points to remember

  • The app picks the language of the phone automatically; we can force one with locale: Locale('hi').
  • Right-to-left languages such as Arabic are handled automatically by Flutter's widgets.
  • Keeping all text in ARB files makes adding a new language easy: just add one more file.
