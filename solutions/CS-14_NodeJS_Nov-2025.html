List three advantages or features of Node.js.

  1. Asynchronous and non-blocking (event-driven). Node does not wait for slow work such as reading a file or a database query. It moves to the next request and handles the result through a callback, so many users are served at the same time.
  2. Very fast. Node runs on Google's V8 engine, which compiles JavaScript directly into machine code.
  3. Single-threaded but highly scalable. One event loop can handle thousands of connections using little memory, which suits chat apps, APIs and live updates.

Other features: one language (JavaScript) for both front end and back end, a huge NPM library of free packages, and it is open source and cross-platform (Windows, Linux, macOS).

Explain Node.js Process Model.

The process model explains how Node.js handles many client requests at the same time. Node.js uses a single-threaded, event-driven, non-blocking I/O model.

Traditional web server model

Servers like Apache or IIS (classic setup) create one thread for each request. While a thread waits for a file or database, it sits idle (it is blocked). Thousands of users need thousands of threads, which uses a lot of memory.

Node.js model

  1. Clients send requests, and Node places them in the event queue.
  2. The event loop, running on one main thread, picks the requests one by one.
  3. If a request is quick (no waiting), it is processed and the response is sent at once.
  4. If a request needs slow I/O (reading a file, a database query, a network call), Node hands it to the thread pool (managed by the libuv library) and moves on to the next request without waiting.
  5. When the slow work finishes, its callback goes back to the queue, and the event loop runs it and sends the response.
JavaScript
const fs = require('fs');

console.log('1. Start');
fs.readFile('data.txt', 'utf8', (err, data) => {
  console.log('3. File reading finished');     // callback runs later
});
console.log('2. Next task runs without waiting');
Output
1. Start
2. Next task runs without waiting
3. File reading finished

Advantages

  • One thread can serve thousands of connections using little memory.
  • Very fast for I/O-heavy apps such as chat, APIs and streaming.

Limitation

CPU-heavy work (image processing, huge calculations) keeps the single thread busy and slows every user. For such work, Node offers worker threads or child processes.

List and explain types of modules with example.

A module is a separate file (or block) of JavaScript code with its own scope, which can be reused in other files. Node.js has three types of modules.

1. Core (built-in) modules

They come with Node.js, so nothing needs to be installed. We load them by name with require(). Examples: http, fs, path, os, url, events, querystring, util, crypto.

JavaScript
const os = require('os');
const path = require('path');

console.log('Platform:', os.platform());       // win32 (on Windows)
console.log(path.extname('notes.pdf'));        // .pdf

2. Local (user-defined) modules

Files we write ourselves in our project. We share code with module.exports and load it with a relative path.

JavaScript
// greet.js
module.exports.sayHello = (name) => `Hello, ${name}!`;
JavaScript
// app.js
const greet = require('./greet');
console.log(greet.sayHello('Riya'));           // Hello, Riya!

3. Third-party modules

Modules made by other developers and shared on the npm registry. We install them first, then load them by name. Examples: express, mysql, lodash, multer.

Terminal
npm install lodash
JavaScript
const _ = require('lodash');
console.log(_.capitalize('node js'));          // Node js
console.log(_.max([4, 9, 2]));                 // 9

Points to remember

  • Each module has its own scope: its variables do not clash with other files.
  • A module is loaded once and cached, so requiring it again is fast.
  • Node also supports ES modules (import / export) in .mjs files or when package.json has "type": "module".

Describe the steps to create a custom module and use it in another file.

A custom module is our own reusable file of code. We export what other files may use, and import it where we need it.

Steps

  1. Create a file for the module, for example mathUtils.js.
  2. Write the functions and values in it.
  3. Export what others should use with module.exports (anything not exported stays private).
  4. In another file such as app.js, import it with require('./mathUtils'). The ./ means "this folder", and .js can be left out.
  5. Use the imported functions.
  6. Run the program with node app.js.
Folder structure
project/
├── mathUtils.js
└── app.js
JavaScript
// mathUtils.js  (custom module)
const PI = 3.14159;

function add(a, b) { return a + b; }
function multiply(a, b) { return a * b; }
function circleArea(r) { return round(PI * r * r); }
function round(n) { return Math.round(n * 100) / 100; }   // private helper

module.exports = { PI, add, multiply, circleArea };
JavaScript
// app.js
const { add, multiply, circleArea } = require('./mathUtils');

console.log('Sum:', add(10, 5));
console.log('Product:', multiply(4, 6));
console.log('Area:', circleArea(3));
Output
Sum: 15
Product: 24
Area: 28.27

Same module with ES module syntax

JavaScript
// mathUtils.mjs
export function add(a, b) { return a + b; }

// app.mjs
import { add } from './mathUtils.mjs';
console.log(add(2, 3));   // 5

Points to remember

  • round() was not exported, so app.js cannot use it; this keeps helper code private.
  • Use either module.exports = {...} or exports.name = ..., but never write exports = {...}, because that breaks the link to module.exports.
  • Custom modules keep the code organised, reusable and easier to test.

1

Describe how the url module can help serve files in an HTTP server.

When the browser asks for a page, the address arrives in req.url, for example /summer.html?lang=en. The url module splits this address, so we can take just the pathname (/summer.html) and ignore the query string. We then turn the pathname into a file name, read that file with fs, and send it. If the file is missing, we send 404.

JavaScript
const http = require('http');
const fs = require('fs');
const url = require('url');

http.createServer((req, res) => {
  const q = url.parse(req.url, true);         // split the URL into parts
  const filename = '.' + q.pathname;           // /summer.html  ->  ./summer.html

  fs.readFile(filename, (err, data) => {
    if (err) {
      res.writeHead(404, { 'Content-Type': 'text/html' });
      return res.end('404 Not Found');
    }
    res.writeHead(200, { 'Content-Type': 'text/html' });
    res.end(data);
  });
}).listen(8080);

Now http://localhost:8080/summer.html shows summer.html, and /winter.html shows winter.html, all with one piece of code. The same parsed object also gives query values through q.query.

Describe the various file operations supported by the fs module with examples.

The fs (file system) module lets Node.js work with files and folders on the computer. We load it with const fs = require('fs');. Every method comes in three forms: callback (fs.readFile), synchronous (fs.readFileSync) and promise (fs.promises.readFile).

Operation Method What it does
Create / write fs.writeFile() Creates a file or replaces its content
Read fs.readFile() Reads the whole file
Append fs.appendFile() Adds data at the end of a file
Open fs.open() Opens a file with a flag (r, w, a)
Rename / move fs.rename() Changes a file's name or folder
Delete fs.unlink() Deletes a file
File details fs.stat() Size, dates, file or folder
Make folder fs.mkdir() Creates a directory
List folder fs.readdir() Gives the names inside a directory
Remove folder fs.rmdir() / fs.rm() Deletes a directory

Example: all operations in one program

JavaScript
const fs = require('fs').promises;

async function demo() {
  await fs.writeFile('notes.txt', 'Hello');                // create / write
  await fs.appendFile('notes.txt', ' World');              // append
  const text = await fs.readFile('notes.txt', 'utf8');     // read
  console.log('Content:', text);

  await fs.rename('notes.txt', 'myNotes.txt');             // rename
  const info = await fs.stat('myNotes.txt');               // details
  console.log('Size:', info.size, 'bytes');

  await fs.mkdir('backup', { recursive: true });           // make folder
  console.log('Folder:', await fs.readdir('.'));           // list folder

  await fs.unlink('myNotes.txt');                          // delete file
  await fs.rmdir('backup');                                // remove folder
  console.log('Cleaned up');
}

demo().catch((err) => console.log('Error:', err.message));
Output
Content: Hello World
Size: 11 bytes
Folder: [ 'app.js', 'backup', 'myNotes.txt' ]
Cleaned up

The same read in all three forms

JavaScript
fs.readFile('a.txt', 'utf8', (err, data) => console.log(data));   // callback
const data = fs.readFileSync('a.txt', 'utf8');                    // synchronous
const data2 = await fs.promises.readFile('a.txt', 'utf8');        // promise (inside async)

(In this small snippet fs is the normal require('fs') module.)

Tip: use the asynchronous forms in servers, so one slow file does not block other users; always handle the error (for example ENOENT when a file is missing).

Explain how to handle HTTP requests in Node.js to serve files based on URLs.

A file server looks at the URL of each request and sends back the matching file from a folder (for example public). For /css/style.css it sends public/css/style.css; if the file is missing, it sends a 404 page.

Steps

  1. Create the server with http.createServer().
  2. Take the pathname from req.url (using the URL class).
  3. If the pathname is /, use /index.html as the home page.
  4. Build the full file path with path.join(__dirname, 'public', pathname).
  5. Pick the Content-Type from the file extension (.html, .css, .png ...).
  6. Read the file with fs.readFile(). If it fails, send 404; otherwise send 200 with the file.
Folder structure
project/
├── server.js
└── public/
    ├── index.html
    ├── about.html
    └── css/style.css
JavaScript
const http = require('http');
const fs = require('fs');
const path = require('path');

const root = path.join(__dirname, 'public');
const types = {
  '.html': 'text/html', '.css': 'text/css', '.js': 'text/javascript',
  '.png': 'image/png', '.jpg': 'image/jpeg', '.json': 'application/json'
};

http.createServer((req, res) => {
  const { pathname } = new URL(req.url, 'http://localhost');     // step 2
  const page = pathname === '/' ? '/index.html' : pathname;        // step 3
  const filePath = path.join(root, page);                           // step 4

  if (!filePath.startsWith(root)) {                                 // block "../" tricks
    res.writeHead(403);
    return res.end('Forbidden');
  }

  const type = types[path.extname(filePath)] || 'application/octet-stream';   // step 5

  fs.readFile(filePath, (err, data) => {                            // step 6
    if (err) {
      res.writeHead(404, { 'Content-Type': 'text/html' });
      return res.end('<h1>404 - File not found</h1>');
    }
    res.writeHead(200, { 'Content-Type': type });
    res.end(data);
  });
}).listen(3000, () => console.log('Server running at http://localhost:3000'));
URL File sent Status
/ public/index.html 200
/about.html public/about.html 200
/css/style.css public/css/style.css (as text/css) 200
/contact.html (does not exist) 404

The correct Content-Type matters: without it the browser may show CSS or images as plain text. In real projects, Express does all of this with one line: app.use(express.static('public')).

What is the purpose of the emit() method in EventEmitter?

emit(eventName, ...args) fires (triggers) an event. It calls every listener registered for that event, one by one in the order they were added, and passes the extra arguments to them. It returns true if the event had listeners, otherwise false.

JavaScript
const EventEmitter = require('events');
const shop = new EventEmitter();

shop.on('sale', (item, price) => console.log(`Sold ${item} for Rs. ${price}`));
shop.emit('sale', 'Pen', 20);        // Sold Pen for Rs. 20
console.log(shop.emit('closed'));    // false, because no listener

Explain the EventEmitter class with example.

Node.js is event-driven: things happen in response to events, such as a request arriving or a file finishing loading. The EventEmitter class from the built-in events module lets us create our own events and respond to them.

How to use it

  1. Load the class: const EventEmitter = require('events');
  2. Create an object: const emitter = new EventEmitter(); (or make a class that extends EventEmitter).
  3. Register a listener with on(eventName, function).
  4. Fire the event with emit(eventName, ...args); every listener of that event runs.
Method Use
on() / addListener() Add a listener that runs every time
once() Add a listener that runs only the first time
emit() Fire an event and pass values
off() / removeListener() Remove one listener
removeAllListeners() Remove all listeners of an event
listenerCount() Number of listeners for an event

Example: a shop

JavaScript
const EventEmitter = require('events');
const shop = new EventEmitter();

function sendBill(item, price) {
  console.log(`Bill: ${item} - Rs. ${price}`);
}

shop.on('order', sendBill);                                   // 1. listeners
shop.on('order', (item) => console.log(`Packing ${item}...`));
shop.once('order', () => console.log('First order of the day!'));
shop.on('error', (err) => console.log('Problem:', err.message));   // always handle errors

shop.emit('order', 'Notebook', 60);                           // 2. fire events
shop.emit('order', 'Pen', 20);
shop.emit('error', new Error('Out of stock'));

console.log('Listeners:', shop.listenerCount('order'));       // 3. inspect and remove
shop.off('order', sendBill);
console.log('After removing:', shop.listenerCount('order'));
Output
Bill: Notebook - Rs. 60
Packing Notebook...
First order of the day!
Bill: Pen - Rs. 20
Packing Pen...
Problem: Out of stock
Listeners: 2
After removing: 1

Explanation

  • Listeners run in the order they were added, and they get the values passed to emit().
  • The once() listener ran only for the first order, then removed itself, so the count is 2.
  • off() removed sendBill, leaving 1 listener.
  • Always add an 'error' listener; without it, emitting 'error' would crash the program.

Many Node objects, such as the HTTP server ('request' event) and streams ('data', 'end'), are built on EventEmitter.

Describe how to connect Node.js to a relational database, and perform INSERT and SELECT operations.

A relational database (such as MySQL) stores data in tables of rows and columns and is used through SQL. Node.js talks to it through a driver package; for MySQL we use mysql or mysql2.

Step 1: Prepare the database (in MySQL)

SQL
CREATE DATABASE college;
USE college;
CREATE TABLE students (
  id INT AUTO_INCREMENT PRIMARY KEY,
  name VARCHAR(50),
  course VARCHAR(20)
);

Step 2: Install the driver

Terminal
npm install mysql2

Step 3: Connect, INSERT and SELECT

JavaScript
const mysql = require('mysql2');

const con = mysql.createConnection({
  host: 'localhost', user: 'root', password: '', database: 'college'
});

con.connect((err) => {
  if (err) throw err;
  console.log('Connected');

  // INSERT a row; ? placeholders are filled from the array
  const sql = 'INSERT INTO students (name, course) VALUES (?, ?)';
  con.query(sql, ['Riya', 'MSc IT'], (err, result) => {
    if (err) throw err;
    console.log('Inserted, new id:', result.insertId);

    // SELECT all rows
    con.query('SELECT * FROM students', (err, rows) => {
      if (err) throw err;
      rows.forEach((r) => console.log(r.id, r.name, r.course));
      con.end();                                   // close the connection
    });
  });
});
Output
Connected
Inserted, new id: 1
1 Riya MSc IT

Same work with async / await

JavaScript
const mysql = require('mysql2/promise');

async function main() {
  const db = await mysql.createConnection({
    host: 'localhost', user: 'root', password: '', database: 'college'
  });
  await db.execute('INSERT INTO students (name, course) VALUES (?, ?)', ['Aman', 'MCA']);
  const [rows] = await db.execute('SELECT * FROM students');
  console.log(rows);
  await db.end();
}
main();

Points to remember

  • Always use ? placeholders for values; they protect against SQL injection.
  • result.insertId gives the new row's id and result.affectedRows gives how many rows changed.
  • Several rows can be inserted together with VALUES ? and a nested array.
  • Close the connection with end() when the work is finished.

What is the purpose of Express in a Node.js application?

Express is a web framework built on top of Node.js. Its purpose is to make building web servers and APIs faster and simpler than with the plain http module. It gives:

What is the use of res.sendFile()?

res.sendFile(path) sends a file (an HTML page, PDF or image) as the response. Express sets the Content-Type from the file extension. The path must be absolute, so we build it with path.join(__dirname, ...). An optional callback reports errors, such as a missing file.

Describe how to handle file uploads in Express using multer.

Multer is a middleware for handling multipart/form-data, the format forms use to send files. It saves the uploaded file and puts its details in req.file (or req.files for many files), and the text fields in req.body.

  1. Install it: npm install multer.
  2. Set where and how files are saved with multer.diskStorage() (or simply multer({ dest: 'uploads/' })). Create the uploads folder first.
  3. Make an HTML form with enctype="multipart/form-data" and a file input.
  4. Add upload.single('photo') (one file) or upload.array('photos', 5) (several) to the route.
  5. Read the file details from req.file.
JavaScript
const express = require('express');
const multer = require('multer');
const app = express();

const storage = multer.diskStorage({
  destination: (req, file, cb) => cb(null, 'uploads/'),
  filename: (req, file, cb) => cb(null, Date.now() + '-' + file.originalname)
});
const upload = multer({ storage, limits: { fileSize: 2 * 1024 * 1024 } });   // max 2 MB

app.post('/upload', upload.single('photo'), (req, res) => {
  res.send(`Saved ${req.file.originalname} (${req.file.size} bytes)`);
});

app.listen(3000);
HTML
<form action="/upload" method="post" enctype="multipart/form-data">
  <input type="file" name="photo">
  <button type="submit">Upload</button>
</form>

The input's name (photo) must match the name given to upload.single().

How to use express.static() to serve static files?

express.static() is a built-in middleware that serves files such as images, CSS, JavaScript and HTML directly from a folder.

  1. Put the files in a folder, usually public.
  2. Add the middleware with app.use().
  3. Open the files in the browser by their path inside the folder; the folder name is not part of the URL.
Folder structure
project/
├── app.js
└── public/
    ├── index.html
    ├── style.css
    └── images/logo.png
JavaScript
const express = require('express');
const path = require('path');
const app = express();

app.use(express.static(path.join(__dirname, 'public')));
app.listen(3000);

Now http://localhost:3000/ gives index.html, /style.css gives the CSS and /images/logo.png gives the picture. To add a prefix, write app.use('/static', express.static('public')), which changes the URL to /static/style.css. Several folders can be added; Express checks them in order.

What are templates in Express? Explain how to configure and use a template engine like EJS or Pug to render dynamic HTML pages.

A template is an HTML file with placeholders and simple logic (loops, if conditions). A template engine fills the placeholders with real data on the server and sends the finished HTML to the browser. This lets one file show different data for each user, such as a name or a list of products, without building HTML strings by hand.

Using EJS (Embedded JavaScript)

Step 1 – Install: npm install ejs

Step 2 – Configure: tell Express which engine to use. Templates are looked for in the views folder by default (change it with app.set('views', folderPath)).

Step 3 – Render: call res.render(fileName, data) in a route.

JavaScript
const express = require('express');
const app = express();

app.set('view engine', 'ejs');                  // configure the engine

app.get('/', (req, res) => {
  res.render('index', {                         // uses views/index.ejs
    name: 'Riya',
    subjects: ['Node JS', 'Flutter', 'Angular']
  });
});

app.listen(3000);

Step 4 – Write the template views/index.ejs:

EJS template
<!DOCTYPE html>
<html>
<body>
  <h1>Welcome, <%= name %>!</h1>
  <ul>
    <% subjects.forEach(function (s) { %>
      <li><%= s %></li>
    <% }); %>
  </ul>
</body>
</html>

The browser receives normal HTML: a heading "Welcome, Riya!" and a list of the three subjects.

EJS tag Meaning
<%= value %> Print a value (HTML is escaped, which is safe)
<% code %> Run JavaScript such as if or loops; prints nothing
<%- include('header') %> Insert another template (a partial)

Using Pug instead

Install with npm install pug, set app.set('view engine', 'pug'), and call res.render('index', {...}) the same way. Pug uses indentation instead of closing tags:

Pug template
html
  body
    h1 Welcome, #{name}!
    ul
      each s in subjects
        li= s
Point EJS Pug
Looks like Normal HTML with <% %> tags Short, indentation-based code
File extension .ejs .pug
Easy for beginners Yes, if you know HTML Needs learning the new syntax

Templates keep the page design (HTML) separate from the server logic, so the code stays clean and pages become dynamic.

Explain how routing works in Express, including route parameters, multiple callbacks, and chaining handlers.

Routing decides which code runs for which URL and HTTP method. A route is written as app.METHOD(path, handler), where METHOD is get, post, put or delete. Express checks routes from top to bottom and runs the first one that matches.

1. Basic routes

JavaScript
app.get('/', (req, res) => res.send('Home page'));
app.post('/students', (req, res) => res.send('Student added'));

2. Route parameters

Parts of the path that start with : capture values into req.params.

JavaScript
app.get('/students/:id', (req, res) => {
  res.send('Student id: ' + req.params.id);       // /students/25  ->  Student id: 25
});

3. Multiple callbacks

A route can have more than one handler function. Each one gets a third parameter, next; calling next() passes control to the next handler. This is useful for checks such as login before the real work.

JavaScript
function checkLogin(req, res, next) {
  if (req.query.token === 'abc123') next();       // allowed: go to the next callback
  else res.status(401).send('Please log in');     // stop here
}

app.get('/profile', checkLogin, (req, res) => {
  res.send('Your profile');
});
// The callbacks can also be given as an array: app.get('/profile', [checkLogin, showProfile])

4. Chaining route handlers

When one path needs several methods, app.route(path) lets us chain them without repeating the path.

JavaScript
app.route('/books')
  .get((req, res) => res.send('List of books'))
  .post((req, res) => res.send('Book added'))
  .put((req, res) => res.send('Book updated'));
Request Output
GET /students/25 Student id: 25
GET /profile?token=abc123 Your profile
GET /profile 401 Please log in
POST /books Book added

5. Modular routes with express.Router()

For big apps, routes are grouped in separate files with express.Router() and attached with app.use('/students', studentRouter). Inside the router, /:id then means /students/:id.

So, routing in Express combines a method, a path (with optional parameters) and one or more handlers, which together decide how each request is answered.
